# 言语康复智能体_Codex开发规范

## 1. 开发目标

本规范用于指导AI辅助开发，保证代码结构稳定、接口一致、方便后续扩展。

原则：

-   先完成MVP闭环
-   不过度设计
-   保持模块边界
-   所有代码可维护

------------------------------------------------------------------------

# 2. 总体架构要求

采用：

    Vue3 + FastAPI + PostgreSQL

结构：

    frontend/

    backend/

    storage/

第一阶段：

-   模块化单体
-   不使用微服务
-   不使用Docker

------------------------------------------------------------------------

# 3. 前端规范

## 技术

必须使用：

-   Vue3
-   TypeScript
-   Vite
-   Vue Router
-   Pinia

## 目录

    src/

    components/
    views/
    router/
    stores/
    api/
    services/
    types/
    utils/

规则：

-   页面放views
-   可复用组件放components
-   API请求统一放api目录
-   不允许页面中直接写axios请求

------------------------------------------------------------------------

# 4. 后端规范

## 技术

使用：

-   FastAPI
-   SQLAlchemy
-   Alembic
-   PostgreSQL

目录：

    app/

    modules/

    core/

    database/

    integrations/

------------------------------------------------------------------------

## 模块原则

每个业务模块独立：

例如：

    agents/

    router.py
    service.py
    model.py
    schema.py

职责：

router：

处理HTTP请求。

service：

处理业务逻辑。

model：

数据库模型。

schema：

请求响应结构。

------------------------------------------------------------------------

# 5. 数据库规范

要求：

-   所有修改使用Alembic
-   禁止直接修改数据库结构
-   主键使用UUID
-   时间统一UTC

禁止：

业务逻辑直接写SQL。

------------------------------------------------------------------------

# 6. AI服务规范

第三方AI服务必须通过：

    integrations/

调用。

禁止：

前端直接调用AI API。

接口需要抽象：

例如：

    ASRProvider

    TTSProvider

    VoiceCloneProvider

方便替换供应商。

------------------------------------------------------------------------

# 7. 文件处理规范

音频、图片不存数据库。

数据库保存：

-   文件ID
-   路径
-   类型
-   所属用户

目录：

    storage/

    avatar/

    voice/

    audio/

    generated/

------------------------------------------------------------------------

# 8. API规范

所有接口：

-   使用REST
-   返回统一格式
-   编写接口文档

命名：

    GET /agents

    POST /agents

    PUT /agents/{id}

    DELETE /agents/{id}

------------------------------------------------------------------------

# 9. 开发顺序

严格按照：

## Phase 1

工程初始化：

-   项目创建
-   数据库连接
-   用户认证

## Phase 2

智能体：

-   创建
-   图片上传
-   声音上传
-   voice_id保存

## Phase 3

训练：

-   跟读
-   场景表达
-   录音上传

## Phase 4

反馈：

-   Mock评分
-   报告

## Phase 5

AI增强：

-   ASR
-   TTS
-   LLM评分

------------------------------------------------------------------------

# 10. Codex工作方式

每次修改前：

1.  阅读已有架构文档。
2.  不改变已有目录结构。
3.  不删除已有功能。
4.  修改数据库必须同步更新Alembic。
5.  新增接口必须更新API文档。
6.  完成功能后提供测试方法。

------------------------------------------------------------------------

# 11. 禁止事项

禁止：

-   一个文件超过合理长度
-   把所有代码写入main.py
-   把数据库逻辑写进router
-   把API密钥写入代码
-   前端保存敏感信息
-   未授权生成用户声音内容

------------------------------------------------------------------------

# 12. 测试要求

每个模块至少包含：

-   正常流程测试
-   异常情况测试

重点测试：

-   登录权限
-   文件上传
-   训练流程
-   数据保存
-   API返回格式

------------------------------------------------------------------------

# 13. 最终目标

代码应支持：

第一阶段：

完成MVP。

第二阶段：

接入真实AI能力。

第三阶段：

扩展：

-   家属端
-   治疗师端
-   App
-   临床系统
