# R0 算法审计与安全止血报告

> 审计日期：2026-09-19  
> 范围：R0，仅覆盖现有链路的单位、阈值、证据准入、旧推荐自动调难与兼容性；不实现 `evaluation_runs`、能力画像 V2 或 Policy V2。  
> 配置版本：`r0-engineering-safety-v1`

## 1. 结论

正式跟读声学链路现统一以 `dBFS` 作为工程口径。`dBA` 仅保留在原始声学输出中的兼容字段：它由未校准的 offset 派生，不进入评分、画像、趋势、家属视图或推荐决策。

历史 `AttemptEvaluation` 因未保存逐条单位与算法版本，不会被重新解释：迁移后仍可通过旧 API 读取，但默认 `decision_eligible=false`，因此不能进入正式画像、趋势或推荐。新写入的过程指标会保存 `unit`、`algorithm_version`、`quality_status` 和 `decision_eligible`。

`phase4.3` 已标记为 `phase4.3-historical-r0-frozen`。趋势仍可作为“观察”，但不再自动改变正式 L/S、训练类型或剂量；需要调整时提示治疗师复核。该工程规则不是临床标准或临床疗效结论。

## 3. 正式证据准入

正式过程证据必须同时满足：

1. `audio_quality=pass` 且过程质量为 `pass`；
2. ASR 非 mock/unknown，且未使用 fallback；
3. 声学 Provider 为 `local`；
4. 过程来源为 `system_rule`；
5. 响度单位明确为 `dBFS`；
6. 算法版本为 `rehab-process-v2`；
7. 新过程指标逐条标记 `decision_eligible=true`。

任一条件不满足，记录可保留用于诊断、重录提示或历史兼容展示，但不会进入正式画像、趋势或自动推荐。对“单位不明”的记录，旧策略保持当前任务坐标并停止正式决策。

## 6. 数据库与 API 兼容

迁移 `0026_r0_algorithm_safety` 为增量迁移：

- 向 `attempt_evaluations` 增加可空 `unit`、`algorithm_version`、`quality_status`，以及默认 `false` 的 `decision_eligible`；
- 更新指标目录中的 `loudness` 定义为 dBFS 工程参考；
- 不覆写历史数值、不推断历史单位；
- `AttemptEvaluationRead` 仅新增可选元数据字段，原有字段保持；
- `TrainingRecommendationRead` 字段与旧路由保持；仅 `policy_version` 标识为冻结历史策略。

## 7. 未在 R0 实现的项目与风险

- 未实现 `evaluation_runs`、V3 采用状态、画像 V2 快照或 Policy V2；这些属于后续 R1–R3。
- `AbilityProfile` 仍是旧表和启发式均值；R0 只收紧其输入，不把 L/S 的语义问题伪装成已经完成。
- 历史未知单位记录从正式趋势和画像中被排除，短期内可能使历史曲线变短；原始记录仍保留可读。
- `loudness_dba` 字段和 `ACOUSTIC_MIN_LOUDNESS_DBA` 环境变量仅为兼容保留。新部署应使用 `ACOUSTIC_MIN_LOUDNESS_DBFS`；未校准 offset 不能支持临床声级结论。
- 工程测试验证的是门控、单位和兼容行为，不构成阈值、权重或训练策略的临床有效性证明。
