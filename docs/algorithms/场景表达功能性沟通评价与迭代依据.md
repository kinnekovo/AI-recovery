# 场景表达：功能性沟通评价与迭代依据

## 1. 产品定位

场景表达不是把一句参考句换成场景图片后的跟读。它训练并观察患者能否在具体生活情境中，以自己的方式组织信息、表达意图，并让沟通对象能够采取合适行动。

因此，场景表达的核心结果是**功能性沟通是否成功**，而不是与某一句标准答案的字面相似度。患者使用同义词、简短句、关键词或符合自身习惯的表达，只要能够传达目标，都应获得正向评价。

本文件是场景表达训练、评分、反馈、趋势和阶段报告的开发依据；与其冲突的“场景题逐字匹配参考句”逻辑视为旧版本。

多轮对话版本的架构、状态机、LLM 协议、数据模型和验收要求以《[场景表达多轮对话训练与评价系统设计](场景表达多轮对话训练与评价系统设计.md)》为准。

## 2. 单次作答评价框架

### 2.1 场景评分契约

每道场景题必须配置一份可审阅、可版本化的评分契约，而不能只配置 `target_text`。契约至少包含：

- `communication_goal`：本题希望沟通对象理解或执行的目标；
- `display_prompt`：患者端展示的自然语言任务；
- `required_information_units`：完成沟通所需的关键信息单元；
- `optional_information_units`：有助于沟通但不强制的补充信息；
- `goal_requirements`：判定“沟通目标已达成”所需的信息单元；
- `prompt_hints`：从轻到重的帮助提示；
- `version`：契约版本和评分方法版本。

信息单元由“语义标签 + 可接受表达”构成。例如医院场景可包含“就医/不适意图”“症状或问题”“希望挂号、检查或咨询”。“我头疼两天了，想挂个号”和“我最近头晕，麻烦帮我看看”都可能完成相同的沟通目标。

### 2.2 评分维度

场景题在患者端优先展示以下结果，而不是一个脱离语境的总分：

| 维度 | 说明 | 单次自动化原则 |
| --- | --- | --- |
| 沟通目标达成 | 听者是否已有足够信息做出正确行动 | 依据 `goal_requirements` 判定“已达成 / 部分达成 / 尚未达成” |
| 关键信息完整度 | 必需信息单元已表达的比例及准确性 | 同义表达等价；不因句子长短额外加分 |
| 场景相关性与组织 | 表达是否围绕任务、是否能基本理解 | 自动结果只作参考；语义置信度低时交治疗师复核 |
| 独立性 | 完成表达所需的提示、帮助与启动等待 | 提示次数和等级必须随作答保存 |
| 沟通修复 | 未被理解后能否补充、改述或澄清 | 仅在有真实追问或澄清回合时评分；未观察到不得伪造分数 |

语速、停顿、无意义重复、响度和可懂度属于**表达过程指标**，与沟通结果并列展示，不能替代沟通结果，也不应因为说得更长而抬高功能性评价。

### 2.3 自动评分边界

自动流程为：录音质量检查 → ASR 及置信度 → 信息单元证据提取 → 确定性规则评分 → 面向患者的反馈。LLM 如被接入，只能提取信息单元证据、生成自然语言反馈；最终等级和数值由可追溯规则层产生。

当前第一阶段使用“配置关键词/短语 + 同义表达词表”的确定性信息单元识别，并明确保存其局限性。它不能理解的表达不得被描述为临床错误；应提示“自动识别不确定，建议治疗师复核”。后续以经过人工标注和校准的语义证据提取器扩展同义表达覆盖，而不是让模型直接给总分。

录音不合格、ASR 置信度不足或评分契约缺失时，不生成正式场景结论。

实现上还应坚持两条不可退化的约束：历史遗留、缺少功能性评分契约的场景材料会在数据库迁移中安全停用（不删除），由治疗师补全后再启用，且不会被下发给患者；ASR 服务降级到模拟结果或不可用时，只保留故障信息，不生成患者成绩、趋势或泛化结论。每次有效作答会固化当时的契约快照、版本、信息单元证据和提示证据，因此后续修改材料不会改写历史复核上下文。当前接入的句级 ASR 未提供可用的词级置信度，因此系统会保存服务来源与失败/降级状态，并把语义不确定性转交治疗师复核；若后续接入具备置信度的 ASR，应在此处加入阈值门控。

## 3. 患者交互设计

患者端应显示“场景 + 想完成的事 + 可自由表达”，不展示或朗读参考答案。可以展示两到三个简短的“试着说清”要点，但不要求逐项照念。

患者可以点击“给我一个提示”。系统按契约从轻到重给出关键词或问题；每次提示都会写入 `prompt_level` 和 `requested_help`，作为独立性证据。训练完成后，应显示：

- 沟通目标是否已经表达出来；
- 已识别的关键信息和下次可补充的一点；
- 语速、停顿、音量等过程性建议；
- 自动分析的适用边界和必要时的治疗师复核提示。

## 4. 康复效果评价

训练内的单次表现与训练效果必须分开。

### 4.1 过程趋势

只在**相同或可比难度、录音质量合格**的任务内比较，并使用基线 3 次和近期 3–5 次有效作答的中位数，而不是单次最高分。重点观察：

- 独立沟通目标达成率；
- 关键信息完整度；
- 平均提示等级；
- 有效信息单位/分钟；
- 长停顿、重复、自我修正和可懂度的趋势。

跟读与场景表达必须分别汇总，不得混合平均。

### 4.2 泛化与维持

评估真实改善时，要加入未训练但难度匹配的平行场景。例如训练“医院挂号”后，可用“药店咨询”或“电话预约”评估。只有在新场景中仍能较独立地完成沟通目标，才可称为能力泛化；只在反复练过的原题上进步，最多说明任务学习。

阶段报告应记录训练后和随访期的维持情况，并区分“训练题改善”“新场景泛化”“日常交流主观改善”。

产品中将“新场景小测”配置为 `evaluation_role = generalization_probe`：它不进入日常推荐任务，不与日常练习平均分混合；系统按实际作答日期（而不是只按次数）统计，至少在两个不同日期完成可比探测、且两日均独立达成沟通目标后，才提示“可能发生泛化”。单次探测或自动识别结果均不能直接作为临床结论。

### 4.3 阶段性临床评估

训练前、训练后及随访时，由治疗师完成或复核 WAB、CADL 及患者/家属报告。系统不得根据日常录音伪造量表分数。可以把自动趋势作为治疗师复核的证据，但不能替代临床评估。

## 5. 产品验收标准

场景表达达到本设计的最低验收条件为：

1. 场景题内容分不再由 `target_text` 字符对齐产生；
2. 每个启用场景题均有版本化评分契约和至少两个关键的信息单元；
3. 患者可自由表述并可请求分级提示；
4. 结果可展示沟通目标、信息单元证据、独立性和过程性指标；
5. 无法可靠判断的维度明确标为“未观察/需复核”；
6. 原始录音、ASR 文本、场景契约版本、证据和提示记录可追溯；
7. 后端单元测试覆盖同义表达、无关表达、提示依赖和“场景题不再字符对齐”；
8. 阶段报告将场景表达与跟读分开，并为后续泛化探测保留任务类型和难度信息。

## 6. 迭代顺序

1. 完成评分契约、确定性信息单元识别、患者端自由表达和提示记录；
2. 完成场景趋势与平行场景探测；
3. 用治疗师双人标注样本校准信息单元和目标达成规则，统计一致性；
4. 在充分验证后接入仅输出证据的语义模型，并持续抽样复核；
5. 结合 WAB、CADL 和患者报告完成阶段性效果评估。

具体的采样、双人盲标、一致性门槛和试点停止条件见《[场景表达临床校准与试点评估方案](场景表达临床校准与试点评估方案.md)》。
