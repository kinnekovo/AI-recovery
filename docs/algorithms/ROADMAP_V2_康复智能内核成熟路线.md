## 1. 路线图换轨声明

2026-09 以前的 Phase 1～6、Phase A～G 文档继续保留，作为历史实现记录；自本路线图起，项目不再以“新增多少功能”作为主要阶段标准，而以以下四类可信度是否提升作为成熟度标准：

1. 自动评估是否来自可用、可追溯、经过质量门控的证据；
2. 能力画像是否准确表达“知道什么、不知道什么、证据够不够”；
3. 训练策略是否稳定、可解释、可复核，不被单次波动驱动；
4. 产品结论是否经过专家校准和真实试用，而不是仅通过工程测试。

阿里云智能体、动态数字人、TTS 和陪伴体验仍可继续开发，但归入独立体验轨道，不再作为康复内核成熟度的替代指标。

## 2. 新的产品核心叙事

本项目下一阶段的核心定位调整为：

> 以可追溯语音与沟通证据为基础，形成患者多维能力画像，并通过可解释、可复核的训练编排策略构成“评估—画像—训练—反馈—再评估”闭环；个性化陪伴智能体负责把该闭环转化为患者愿意持续参与的交互体验。

系统是康复训练辅助工具，不自动诊断，不把未经校准的工程分数表述为临床能力，不替代治疗师的量表施测与专业判断。

## 3. 当前系统基线

### 3.1 已形成稳定工程基础的部分

以下能力原则上进入维护状态，后续只做兼容性、可靠性与安全性改进：

- 患者、家属、治疗师三端及认证、授权、绑定和访问控制；
- 训练计划、训练会话、任务、作答、文件和录音存储主链路；
- ASR、声学分析、TTS、发音评测、LLM、数字人等 Provider 抽象；
- 无效录音、mock Provider、ASR 失败等基础门控；
- 算法版本、Provider 来源、部分配置快照和原始输出留存；
- 跟读训练、单题反馈、趋势展示、治疗师复核入口；
- 多轮场景会话、状态机、语义证据抽取、泛化探测骨架；
- 腾讯 SOE 发音评测、韵律分析、人工可懂度记录和追加式修正的影子链路；
- 阶段评估记录与 WAB/CADL/接受度的基础存储；
- 当前 25 个数据库迁移、110 个后端测试方法所覆盖的工程边界。

### 3.2 已实现但仍是实验性规则的部分

| 模块 | 当前实现 | 当前性质 | 主要限制 |
| --- | --- | --- | --- |
| 跟读过程评估 | `rehab-process-v2` | E1：内部可重复规则 | 字符对齐受 ASR 误差影响；“错误事件”并非构音错误；参考区间未校准 |
| 综合评分 | `rehab-score-v2` | E1 | 权重和阈值为工程初值；总体分可能掩盖证据缺失 |
| 精细发音 | `rehab-pronunciation-v1-shadow` | E1 影子能力 | 厂商教育场景分数尚未完成康复场景校准，不得替代正式评分 |
| 单题场景评估 | `scenario-information-units-v1` | 历史兼容 | 关键词契约为主，不代表成熟语义理解 |
| 多轮场景评估 | `scenario-dialogue-rules-v1` | E1 | 证据复核后尚未确定性重算；画像尚未消费该域的正式结果 |
| 能力画像 | `ability_profiles` + 最近 10 次跟读均值 | E0/E1 | 以跟读为主；L/S 被误作患者能力等级；`confidence` 是样本启发式权重 |
| 训练推荐 | `phase4.3` | E0/E1 | 硬编码阈值；领域混合；单位漂移；缺少防抖与冷却期 |
| 推荐效果 | 首条与最新一条指标差 | E0 | 只能称“推荐后观察”，不能作因果归因 |
| 阶段评估 | `assessment_sessions` | E1 数据容器 | 量表版本、施测条件、原始条目结构和可比性门控仍不足 |

成熟度定义：

- E0：工程占位或概念规则；
- E1：内部可重复、可测试，但未完成专家校准；
- E2：经治疗师标注校准，边界和误差可说明；
- E3：完成小规模真实试用，稳定性与偏差可报告；
- E4：在明确适用范围内作为稳定产品能力持续监控。

### 3.3 当前必须优先修复的断点

这些问题在新增功能之前处理：

1. **响度单位漂移。** `recommendation_policy.py` 仍使用 `low_loudness=60`、`target_loudness=69`，正式过程指标已使用约 `-35~-12 dBFS`；这会使真实的负值响度几乎总被判为“偏轻”，趋势接近目标值的判断也失真。`family_voice_percent()` 仍以 69 为目标，存在同类问题。
2. **场景评估与画像断开。** 多轮场景已写入 `scenario_dialogue_evaluations`，但画像仍主要读取跟读 Attempt 和旧的 `scenario_expression_reviews`，新场景能力没有进入正式画像。
3. **复核没有成为新事实。** 多轮场景治疗师接口会保存 `evidence_overrides`，但当前没有基于修订证据重算维度和总结果的完整链路。
4. **L/S 语义混淆。** `current_content_level/current_autonomy_level` 由跟读均值直接推断，却又被推荐层当作患者能力和任务难度坐标；两种含义必须拆开。
5. **`confidence` 命名过度。** 画像 `confidence` 实际由最近作答数、阶段复核数、场景复核数加权；它不是统计置信度，应迁移为 `evidence_sufficiency` 或支持等级。
6. **推荐防抖不足。** 当前推荐后只要首条与最新一条出现两个积极或消极信号，就可升降 L/S；没有连续窗口、改变冷却期、可比性门控和“一次只改一轴”。
7. **推荐复核优先级未收口。** `include_review_override` 参数没有形成清晰的“患者端采用治疗师有效覆盖”的策略；治疗师复核记录与系统推荐可能并存但不生效。
8. **领域指标仍被混合。** 推荐效果统一汇总四个跟读指标；多轮场景的目标达成、信息充分性、回应和修复未进入领域专属效果观察。
9. **测试覆盖偏工程链路。** 质量门控、过程引擎、场景状态机、Provider 和权限已有测试，但推荐策略、画像聚合、单位一致性、复核后重算和跨版本迁移缺少系统测试。
10. **阶段量表仍是轻量容器。** 当前 WAB/CADL 字段可记录分数，但缺少量表版本、原始条目、施测人资质、设备环境、可比性判断等正式字段。

## 4. V2 路线的不可退化原则

后续实现必须遵守以下约束：

- mock、fallback、低质量录音、缺失契约和不可验证证据不得进入正式画像和自动调难；
- 跟读、功能性场景沟通、阶段临床评估是三个独立评价域；
- 发音/韵律影子结果在完成校准前不得改变患者正式分数；
- L×S 只描述任务难度和支持程度，不直接作为患者能力标签；
- 原始证据、自动结果、人工修订和最终采用值必须同时可追溯；
- 患者端优先显示证据化反馈和一个可行动建议，不突出未经验证的总分；
- 推荐层只读取通过准入门控的画像快照，不直接拼接底层任意指标；
- 一次波动不自动升级；一次下降原则上先观察，除非存在安全或明显负担问题；
- 推荐变化必须说明“依据了哪些证据、改变了什么、为什么没有改变其他轴”；
- 工程测试只能证明实现符合定义，不能证明临床有效。

## 5. 四条并行成熟轨道

### Track A：康复评估可信度

目标：把现有多个评分链路统一为版本化、分域、可追溯的评估 V3。

主要交付：

- 统一证据准入与质量状态；
- 跟读域 V3、场景沟通域 V3、阶段临床评估域的独立结果；
- 精细发音继续以 shadow 方式接入；
- 自动结果与人工修订的确定性重算；
- 统一单位、算法配置快照、输入来源和限制声明；
- 历史 V2 结果只读兼容与双读验证。

完成标志：任一展示指标都能回答“来自哪段录音/哪次对话、什么算法、什么单位、是否可进入画像、是否被人工修订”。

### Track B：能力画像与训练策略

目标：形成多维证据画像和稳定的 Training Policy，而不是继续扩大硬编码 if。

主要交付：

- 跟读能力与功能沟通能力分域画像；
- `evidence_sufficiency`、新鲜度、可比性和趋势稳定性；
- 任务难度 L×S 与患者能力彻底解耦；
- 策略输入/输出契约、证据门控、防抖、冷却期和任务多样性；
- 治疗师覆盖规则及失效时间；
- 推荐后观察按域统计，不再声称因果“效果”。

完成标志：策略在同一输入快照下可重复产生同一结果；低质量或证据不足不会改变难度；策略变化有完整理由链。

### Track C：真实试用与临床校准

目标：用去标识化、获授权的真实数据决定阈值、权重、适用范围和停止条件。

主要交付：

- 标注手册、双治疗师复核、冲突裁决和版本管理；
- 跟读对齐、发音片段、场景信息单元、回应/修复的标注集；
- 一致性、绝对误差、重测稳定性、失败模式和亚组偏差报告；
- 保留集验证及回归基准；
- 小规模试用的可用性、依从性和安全事件记录；
- 每个规则从 E0/E1 向 E2/E3 晋级的证据包。

完成标志：任何对外使用的阈值和结论都能指向校准数据、版本、适用人群与限制。

### Track D：陪伴智能体与产品体验

目标：在不改变康复证据的前提下，提高可理解性、可访问性和长期使用意愿。

主要交付：

- 阿里云数字人、TTS、形象与声音的稳定集成；
- 低认知负担、单任务、可重录、可暂停和可恢复的训练体验；
- 患者、家属、治疗师分角色展示；
- 陪伴话术与康复结论解耦；
- 无数字人/Provider 失败时的可用降级体验。

完成标志：关闭阿里云智能体后康复内核仍完整可用；体验层不能修改评估证据与策略决策。

## 6. 发布里程碑与门禁

里程碑按证据门禁推进，不按固定日期自动进入下一阶段。

### R0：算法审计与安全止血

交付：

- 修复所有 dBA/dBFS 混用及目标值错误；
- 建立阈值、权重、单位、Provider、fallback、算法版本审计表；
- 为每个算法模块标注 E0～E4 成熟度；
- 新增推荐单位一致性、画像准入和 mock 隔离测试；
- 暂停未经门控的自动升降级。

退出条件：真实 `dBFS` 不再触发旧 dBA 阈值；所有患者可见结论均有来源和限制。

### R1：评估引擎 V3 双轨运行

交付：

- 新的 canonical evaluation run 与维度结果；
- 跟读、场景、阶段评估三域分开；
- V2 与 V3 同时计算但 V3 暂不驱动患者难度；
- 复核修订可以确定性重算；
- 患者端弱化 overall score，治疗师端保留原始证据。

退出条件：固定回归样本上 V3 可重复；V2/V3 差异有报告；无效证据不会生成正式 V3 结果。

### R2：能力画像 V2 影子运行

交付：

- 多维、分域画像快照；
- 新的证据充分度和趋势稳定性；
- 多轮场景正式接入画像；
- L/S 从画像字段中退出，保留为任务坐标；
- 患者/家属/治疗师三种视图。

退出条件：画像每个维度都可回溯证据；证据不足显示“尚不足”，不填充假分数；旧画像只读兼容。

### R3：训练编排 Policy V2 影子与顾问模式

交付：

- 证据门控、主要目标选择、保持/强化/升级/降级/换维度决策链；
- 连续窗口、防抖、冷却期、一次只改一轴；
- 领域专属效果观察和任务多样性控制；
- 治疗师覆盖优先级和有效期；
- shadow → therapist-advisory 两种开关。

退出条件：历史回放不出现频繁 L/S 横跳；同输入同输出；治疗师能看懂并覆盖建议；策略仍不自动作临床结论。

### R4：校准试点与受控启用

交付：

- 双标数据和一致性报告；
- 阈值与权重校准记录；
- 失败模式、亚组偏差、停止条件；
- 受控小规模真实使用；
- 从 advisory 到 active 的审批记录。

退出条件：达到各模块预先定义的 E2/E3 门槛；没有达到门槛的模块继续保持 shadow 或人工复核。

每次算法变更必须同时更新：

- 算法/策略版本；
- 配置快照；
- 数据迁移或兼容方式；
- 自动测试与固定回归集；
- 成熟度等级及其证据；
- 患者端文案边界；
- 已知限制和回滚方式。

## 9. 近期开发顺序

在不扩张任务范围的前提下，建议按以下顺序执行：

1. 完成 R0：单位、阈值、数据源和旧/新场景链路审计；
2. 建立评估 V3 的统一运行记录和准入状态；
3. 先迁移跟读，再迁移多轮场景，最后扩展阶段评估；
4. 让画像 V2 只读取 V3 的正式或经复核结果；
5. 让 Policy V2 先 shadow 回放，再进入治疗师顾问模式；
6. 建立标注集和校准报告后，再决定是否启用自动调难；
7. 有足够真实、纵向、跨患者数据后，才评估 learning-to-rank、contextual bandit 等数据驱动方法。

## 10. 总体验收标准

本路线进入“受控试点”前必须同时满足：

- 跟读、场景、阶段临床评估没有共用一个含义模糊的总分；
- 所有正式指标单位一致、来源可追溯、算法版本可复现；
- mock、fallback、低质量和证据不足不会进入画像或自动调难；
- 场景人工复核会产生新的确定性结果，而不是仅保存备注；
- 画像不再把 L/S 当作患者能力等级；
- `confidence` 已按语义拆分为测量质量、证据充分度或模型置信度；
- 推荐策略具备防抖、冷却期、可比性门控和人工覆盖；
- 推荐后变化被表述为观察，不被误写为康复效果的因果证明；
- 每个核心规则都有单元测试、边界测试和历史回放测试；
- 每个患者可见结论均有适用边界和一个清晰、非羞辱性的下一步建议；
- 临床有效性声明只来自预先设计并通过审核的验证研究。

## 11. 明确不在本轮承诺中的事项

- 不承诺自动诊断失语症、构音障碍或言语失用症；
- 不承诺 WAB/CADL 的自动施测或自动解释；
- 不把腾讯 SOE 分数直接称为临床构音分；
- 不在数据不足时上线黑盒机器学习推荐；
- 不以数字人效果、模型响应自然度替代康复算法验证；
- 不在没有对照设计时声称推荐导致了康复改善。
