# 患者能力画像 V2：多维证据模型

> 文档版本：2.0-draft  
> 基线日期：2026-09-18  
> 上游依赖：`评估引擎V3设计.md`  
> 下游消费者：`推荐策略V2_训练编排Policy.md`

## 1. 文档目标

能力画像 V2 不再试图用 `L3/S3 + 四个均值 + confidence` 概括患者。它的职责是：

- 按训练域描述当前已有的能力证据；
- 明确哪些维度证据充分、哪些尚不足或过期；
- 区分本次表现、近期稳定状态和阶段临床变化；
- 为训练编排提供可解释、可追溯的输入；
- 防止低质量、mock、fallback、不可比和未复核结果进入策略。

画像是根据证据计算出的**版本化快照**，不是患者永久标签，也不是医学诊断。

## 2. 当前画像的真实含义与问题

当前 `AbilityProfile` 由最近最多 10 次有效跟读记录生成，保存：

- `current_content_level`；
- `current_autonomy_level`；
- `avg_script_accuracy_recent`；
- `avg_error_count_recent`；
- `avg_speech_rate_recent`；
- `avg_loudness_recent`；
- 文本总结、推荐、`confidence` 和 evidence 计数。

现有实现已经做对了两点：拒绝低质量音频、ASR fallback、mock ASR/声学和 mock process evaluation；保存近期作答数、阶段复核数和场景复核数。

但它仍有五个核心问题：

1. **画像几乎等于跟读均值。** 新多轮场景结果没有进入核心维度；
2. **L/S 语义错误。** L×S 原本是任务难度坐标，却被存成患者能力级别；
3. **平均值丢失证据结构。** 不同任务难度、提示水平、日期和设备被直接混合；
4. **`confidence` 不是置信度。** 当前 0.55/0.30/0.15 只是样本计数与复核计数的工程加权；
5. **画像和推荐耦合。** 画像表直接保存 recommendation 文本，使“描述能力”和“决定练什么”边界不清。

## 3. V2 核心原则

- 分域：跟读能力与功能性沟通能力分别计算；
- 分维：画像不先压成单一总分；
- 有空值：证据不足时明确返回 `insufficient`，不填默认低分；
- 可追溯：每个维度都指向采用的 evaluation run；
- 可比较：不同任务类型、难度、提示和评估版本不能无条件平均；
- 有时效：旧证据保留，但过期后降低当前决策权重；
- 有人工优先级：经复核的证据优先于未复核自动证据；
- 无诊断：画像描述训练表现，不推断疾病类型或严重程度；
- 与策略解耦：画像只描述状态，Policy 决定任务。

## 4. 画像总体结构

建议的逻辑结构：

```json
{
  "profile_version": "ability-profile-v2.0",
  "patient_profile_id": "...",
  "as_of": "...",
  "repeat_profile": {},
  "functional_communication_profile": {},
  "clinical_stage_summary": {},
  "evidence_state": {},
  "readiness_observations": {},
  "limitations": []
}
```

其中：

- `repeat_profile`：固定目标内容下的复现、发音证据、流利、声音状态和独立性；
- `functional_communication_profile`：生活场景中的目标达成、信息、回应、组织、独立性和修复；
- `clinical_stage_summary`：WAB/CADL/人工可懂度的最近有效阶段结果，只作独立摘要；
- `evidence_state`：证据数量、日期跨度、新鲜度、复核比例和版本；
- `readiness_observations`：对某类任务的近期准备度，不等同于患者等级；
- `limitations`：数据不足、Provider 限制、不可比条件等。

## 5. 分域维度

### 5.1 跟读画像

| 维度 | 来源 | 初期聚合对象 | 解释边界 |
| --- | --- | --- | --- |
| `content_reproduction` | V3 内容复现 | 同难度/相近文本长度的完成率与遗漏模式 | 不等于构音准确性 |
| `articulation_evidence` | SOE + 治疗师修订 | 经复核片段或 shadow 摘要 | E2 前不驱动自动调难 |
| `fluency_efficiency` | 表达/发音速率、停顿 | 同类任务内的稳健中心与波动 | 不以越快越好 |
| `voice_stability` | dBFS、波动、韵律 | 同设备/相近环境内变化 | 未校准时不作临床正常判断 |
| `independence` | 提示、求助、启动延迟 | 完成任务所需支持 | 必须与任务难度同时解释 |

### 5.2 功能性沟通画像

| 维度 | 来源 | 初期聚合对象 | 解释边界 |
| --- | --- | --- | --- |
| `goal_achievement` | 多轮场景 adopted run | 同类场景独立达成率 | 训练与泛化探测分开 |
| `information_sufficiency` | 必需信息单元 | 每段对话的充分性中位数 | 不因说得更长加分 |
| `response_ability` | 问题—回应证据 | 有效回应率 | 不能复用信息单元数代替 |
| `relevance_organization` | 独立结构化证据/复核 | 相关性和基本组织 | 自动值低可信时须复核 |
| `independence` | 会话提示轨迹 | 无提示完成率、平均提示等级 | 与场景复杂度共同解释 |
| `repair_ability` | 真实 repair 回合 | 已观察回合中的成功率 | 未观察必须为空 |

### 5.3 阶段临床摘要

画像可展示最近一次可比的 WAB/CADL/人工可懂度记录及变化量，但不得把日常自动分数映射为量表分，也不得用量表结果直接覆盖日常训练域。

示例：

```json
{
  "instrument": "CADL",
  "version": "...",
  "latest_score": 88,
  "change_from_comparable_baseline": 6,
  "comparability": "comparable",
  "review_status": "confirmed",
  "interpretation": "记录到总分变化 6；未配置临床意义阈值"
}
```

## 6. 单维度证据对象

每个画像维度统一返回：

```json
{
  "dimension": "content_reproduction",
  "status": "supported",
  "estimate": 84.0,
  "unit": "%",
  "band": "developing",
  "trend": "stable",
  "trend_stability": "provisional",
  "evidence_sufficiency": "supported",
  "sample_count": 6,
  "distinct_days": 3,
  "reviewed_count": 2,
  "window_start": "...",
  "window_end": "...",
  "evidence_run_ids": ["..."],
  "comparison_scope": {
    "domain": "repeat",
    "task_family": "simple_sentence",
    "content_level": "L3"
  },
  "limitations": []
}
```

字段说明：

- `status`：`insufficient/provisional/supported/reviewed/stale`；
- `estimate`：当前工程估计，可空；
- `band`：便于阅读的训练观察档位，阈值必须版本化且标明成熟度；
- `trend`：`improving/stable/declining/mixed/not_available`；
- `trend_stability`：趋势是否有足够连续证据；
- `evidence_sufficiency`：证据支持程度，不使用 `confidence`；
- `comparison_scope`：说明该值只适用于哪些任务与条件。

## 7. 证据准入

### 7.1 必须满足

画像 V2 只读取评估 V3 中：

- `result_status=formal`，或经治疗师采用的 `provisional`；
- `profile_eligibility=true`；
- `source_type`、算法版本和单位完整；
- 未被更新的 adopted run 替代；
- 与画像维度定义一致的 domain；
- 非 mock、非 fallback、非低质量；
- 非泛化探测训练数据，除非更新专门的 generalization 子画像。

### 7.2 必须排除

- `rehab-process-v2` 的历史 mock 结果；
- 旧单题场景的关键词兼容结果；
- 多轮场景中 `pending_semantic_review` 且未复核的正式结论；
- SOE disabled/failed 的空结果；
- 量表版本不明或施测条件不可比的变化量；
- 未明确单位的 loudness；
- 被人工修订 run 替代的旧自动 run；
- 同一次训练的重复写入或接口重试副本。

## 8. 聚合规则 V2.0

以下规则是首版工程基线，成熟度 E1，必须配置化并用标注数据校准。

### 8.1 时间窗口

- 每个域独立取最近 30 天内最多 10 个有效结果；
- 至少覆盖 2 个不同日期才生成趋势；
- 只在相同或可比的 task family 内计算数值趋势；
- 30 天外结果保留在长期时间线，但默认不代表当前状态；
- 治疗师可设置特殊情况下的窗口，但必须留下原因。

### 8.2 支持等级

| 等级 | 初始工程条件 | 可用于策略 |
| --- | --- | --- |
| `insufficient` | 少于 3 个有效结果，或仅 1 天 | 只用于“继续收集证据” |
| `provisional` | 至少 3 个结果且覆盖 2 天 | 可给建议，不自动调难 |
| `supported` | 至少 5 个结果、覆盖 3 天、质量一致 | 可进入 Policy 防抖窗口 |
| `reviewed` | supported 且关键证据经治疗师复核 | 可提高策略优先级 |
| `stale` | 最近有效证据超过配置时限 | 不自动调难 |

数量只是最低条件，不代表统计置信。若任务不具可比性、设备变化显著或证据相互冲突，应降级。

### 8.3 聚合统计

- 比例/连续数值优先使用中位数和四分位范围，避免单次异常拉动；
- 目标达成使用可比场景中的比例，并同时报告分母；
- 提示等级报告中位数、无提示完成率和最大提示等级；
- 错误/事件报告每任务或每有效字符的率，不只报告绝对次数；
- 人工复核值优先，但不删除自动原值；
- 不同算法版本原则上不直接合并；确需合并时必须有版本桥接验证。

### 8.4 趋势规则

趋势至少需要 5 个可比结果、3 个不同日期和不低于 `supported` 的证据等级。V2.0 首版使用稳健斜率或前后两个小窗口的中位数差，不使用“第一条 vs 最新一条”。

趋势输出必须同时包含：方向、变化量、波动、样本数、日期跨度和稳定性。若改善和恶化信号并存，输出 `mixed`，不强行归为进步或退步。

## 9. L×S 与画像解耦

### 9.1 新定义

L×S 只属于 `TaskTemplate` 和训练策略：

- L：任务内容/语义复杂度；
- S：完成任务时允许的支持程度或自主要求。

画像不再保存 `current_content_level/current_autonomy_level` 作为患者能力。

### 9.2 任务准备度

为了让 Policy 能选难度，画像提供 `readiness_observations`，但它描述“最近在某类任务上的表现”，不宣称患者属于某一级。

示例：

```json
{
  "task_family": "repeat.simple_sentence",
  "observed_at": {"content_level": "L3", "autonomy_level": "S2"},
  "status": "supported",
  "completion_pattern": "stable_with_keyword_prompt",
  "evidence_run_ids": ["..."]
}
```

Policy 可以据此决定下一次保持 L3/S2 或只调整一个轴，但画像本身不输出“患者能力=L3/S2”。

### 9.3 建议的领域化 L 定义

同一个 L 在不同训练域使用独立 rubric：

| L | 跟读示例 | 场景示例 |
| --- | --- | --- |
| L1 | 音节、单词 | 熟悉单一意图、1 个关键信息 |
| L2 | 短语 | 熟悉单一目标、2 个信息单元 |
| L3 | 简单句 | 2～3 个信息单元、一次自然追问 |
| L4 | 复杂句/短段落 | 多步目标、确认或澄清 |
| L5 | 连续表达/脚本段落 | 新场景、信息整合和修复机会 |

S1～S4 仍表示从完整示范到自主完成，但提示类型、次数和允许的帮助必须在任务契约中明确。

## 10. 数据模型

建议新增 `ability_profile_snapshots`，而不是继续原地覆盖唯一一行：

| 字段 | 含义 |
| --- | --- |
| `id` | 快照 ID |
| `patient_profile_id` | 患者 |
| `profile_version` | `ability-profile-v2.0` |
| `as_of` | 计算截止时间 |
| `repeat_profile` | 分维 JSONB |
| `functional_communication_profile` | 分维 JSONB |
| `clinical_stage_summary` | 阶段评估摘要 |
| `evidence_state` | 数量、日期、复核、新鲜度 |
| `readiness_observations` | 按任务族的观察 |
| `source_run_ids` | 采用的 V3 runs |
| `generation_config` | 窗口、聚合、band 阈值快照 |
| `status` | `shadow/adopted/superseded` |

快照不可变。新证据、算法升级或人工复核后生成新快照，旧快照保留，便于推荐回放和审计。

现有 `ability_profiles` 的迁移策略：

1. 保留旧表只读；
2. 将旧行映射为 `legacy_profile_snapshot`，标记 `not_policy_eligible`；
3. V2 shadow 期同时计算新旧画像并输出差异；
4. Policy V2 只读取 adopted 的 V2 快照；
5. 稳定后停止写旧字段，但保留历史 API 兼容一段时间。

## 11. 场景结果接入画像

新的功能沟通画像只读取 `ScenarioDialogueEvaluation` 对应的 V3 adopted run，且必须：

- 使用多轮完整会话；
- 将 training 与 generalization_probe 分开；
- 采用治疗师修订后重算的最终证据；
- `repair_ability` 只统计真实已观察回合；
- 对话契约版本可识别；
- mock ASR、fallback 语义匹配和低置信度未复核结果不准入。

旧 `ScenarioExpressionReview` 只保留为历史证据计数，不能再提高新画像的 evidence sufficiency。

## 12. 三端展示

### 患者端

显示：

- 最近比较稳定的两项优势；
- 当前最值得练习的一项；
- “证据还在积累/已有多次记录支持”的通俗说明；
- 分开的“跟读练习”和“生活沟通”卡片；
- 变化使用“最近几次更稳定”等谨慎表述。

不显示：统计置信度、复杂权重、疾病等级、未经复核的构音结论。

### 家属端

显示训练参与、可观察变化和陪伴建议。依从性、训练次数和情绪反馈单列，不能被包装为语言能力提升。

### 治疗师端

显示完整分域维度、证据 run、任务难度、日期分布、复核状态、Provider 限制、趋势稳定性、算法版本和画像差异。

## 13. API 目标

- `GET /profiles/ability-v2`：患者自己的 adopted 快照；
- `GET /therapist/patients/{id}/ability-v2`：专业完整视图；
- `GET /profiles/ability-v2/history`：版本化快照；
- `POST /profiles/ability-v2/rebuild`：管理员/受控任务重建；
- `GET /profiles/ability-v2/evidence/{dimension}`：维度证据列表；
- `GET /profiles/readiness?task_family=`：供 Policy 使用的稳定契约。

返回值中必须有 `profile_version`、`as_of`、`evidence_sufficiency`、`source_run_ids` 和限制。

## 14. 画像生成流程

```text
读取 adopted V3 runs
  → 按 domain 和 dimension 分组
  → 执行准入门控
  → 按 task family / 难度 / 支持程度建立可比组
  → 计算稳健中心、波动和趋势
  → 评定 evidence sufficiency
  → 生成 readiness observations
  → 固化不可变 snapshot
  → Policy 读取 snapshot_id
```

画像重建应幂等：同一组 source run 与同一 generation config 必须得到等价结果。

## 15. 测试要求

### 必须新增

- 新多轮场景 adopted run 能进入场景画像；
- 旧单题场景和未复核 fallback 不进入；
- mock、低质量、fallback、superseded run 被排除；
- 不同单位或算法版本不被直接平均；
- `repair_ability=not_observed` 不产生 0 分；
- 少于最低证据时 estimate 可为空且 status=insufficient；
- 同证据同配置生成相同快照；
- 人工修订后生成新快照并引用新 run；
- L/S 不再作为画像等级输出；
- generalization probe 与日常训练分开；
- 阶段量表不可比时不生成变化结论；
- 患者端接口不返回审计敏感字段。

### 历史回放

选择至少以下患者轨迹：

- 只有 1～2 次跟读；
- 多次跟读但集中在同一天；
- 跟读稳定、场景证据不足；
- 跟读一般但场景目标多次独立达成；
- 提示依赖下降但内容复现波动；
- Provider 版本切换；
- 人工复核大幅修订自动结果；
- 长时间无训练后重新开始。

## 16. 完成标准

画像 V2 完成必须满足：

1. 跟读、功能沟通、阶段临床摘要分开；
2. 每个维度有证据状态、样本数、日期、复核和来源 run；
3. 证据不足时允许为空，不用默认低分；
4. `confidence` 已迁移为明确语义的字段；
5. L/S 只存在于任务/准备度上下文，不是患者能力等级；
6. 多轮场景复核结果正式进入画像；
7. 旧单题场景、mock 和 fallback 不进入；
8. 聚合使用可比组和稳健统计，不再简单平均所有最近记录；
9. 快照不可变、可回放、可重建；
10. Policy 可以只通过稳定 API 读取 adopted 快照，不访问底层散表。
