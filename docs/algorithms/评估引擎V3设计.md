# 康复评估引擎 V3 设计

> 文档版本：3.0-draft  
> 基线日期：2026-09-18  
> 上位文档：`ROADMAP_V2_康复智能内核成熟路线.md`  
> 下游消费者：`能力画像V2_证据模型.md`、`推荐策略V2_训练编排Policy.md`

## 1. 文档目标

V3 的目标不是再增加一个“更复杂的总分”，而是把当前散落在过程指标、综合评分、精细发音、单题场景、多轮场景和阶段量表中的结果，重构为一套分域、可追溯、可复核、可校准的证据系统。

V3 必须回答六个问题：

1. 这条结果属于跟读、功能性沟通还是阶段临床评估？
2. 原始音频、转写、契约和 Provider 是否可用？
3. 哪些维度被实际测量，哪些维度不可用或尚未观察？
4. 数值、单位、算法、阈值和配置是什么版本？
5. 自动结果是否经过人工确认或修订？
6. 该结果能否进入画像、趋势和训练策略？

## 2. 当前实现基线

### 2.1 跟读链路

当前主链路为：

```text
Attempt + audio
  → ASR
  → LocalAcousticAnalysisProvider
  → rehab-process-v2
  → rehab-score-v2
  → AttemptEvaluation / AttemptAnalysisResult / AttemptScore
  → ability_profiles / recommendation
```

已有优点：

- ASR mock、声学 mock 和录音质量不通过时会阻止正式评分；
- 保存表达速率、发音速率、停顿、重复、自我修正、提示依赖和来源版本；
- LLM 只生成反馈文案，不能控制规则分数；
- `script_mismatch_events` 与过程错误事件已部分分离；
- 精细发音以 shadow 字段写入，不覆盖 `rehab-score-v2`。

主要问题：

- `script_accuracy` 实质是 ASR 文本与目标文本的字符对齐，不能单独代表构音准确性；
- `clarity_score` 实际由重复、自我修正、长停顿、插入语扣分，不是严格意义的清晰度；
- 180～240 字/min、-35～-12 dBFS、提示扣分和各维度权重均为待校准工程值；
- 总分会把不可用维度压成可比较的单一数字；
- 结果表中 `confidence` 同时承载质量、来源和可信程度，语义不够清楚；
- 发音 shadow score 在部分证据缺失时仍把缺失项按 0 参与组合，和“不可用不等于 0”的设计原则不完全一致。

### 2.2 场景沟通链路

代码库目前同时存在两条场景链路：

- 历史单题场景：借用 `Attempt`、`rehab-process-v2` 和 `scenario-information-units-v1`；
- 新多轮场景：`ScenarioDialogueSession/Turn/Evaluation` + 状态机 + 结构化语义证据 + `scenario-dialogue-rules-v1`。

新多轮链路已经具备正确方向：按完整对话评价目标达成、信息充分性、回应、相关性、独立性和修复；LLM 只抽取证据或改写角色回复；低置信度、fallback 和 mock ASR 不生成正式总分。

仍需补齐：

- 语义证据只验证逐字引用和置信度，不等于已经完成治疗师校准；
- `response_score` 与 `relevance_score` 当前都近似由“该回合是否提取到信息单元”计算，两个维度尚未真正分离；
- 人工 `evidence_overrides` 保存后没有形成新的重算结果；
- 修复分虽只在真实 repair 回合计算，但总分固定加权时需在未观察时重新归一化；
- 多轮场景结果尚未成为能力画像的正式输入；
- 历史单题场景和新多轮场景的展示、趋势和推荐准入边界尚未完全冻结。

### 2.3 阶段临床评估链路

`AssessmentSession` 已能保存 WAB、CADL 和接受度相关字段，并支持基线/过程中/30 天/训练后比较。

当前应视为“阶段评估数据容器”，而不是完整临床量表系统，原因包括：

- 未强制保存量表正式版本和本地化版本；
- 未保存原始条目、分量表计算过程和缺失条目；
- 未完整记录施测者、设备、环境、用时和偏离标准流程情况；
- 当前比较只计算数值差，没有判断两次记录是否可比；
- 没有经过验证的 MCID 时，系统不应自动输出“显著改善”。

## 3. V3 总体架构

```text
原始输入
  ├─ 录音 / 文件 / 设备信息
  ├─ ASR / SOE / 声学 / LLM 输出
  ├─ 任务模板或场景契约快照
  └─ 提示、求助、启动延迟、对话状态
             ↓
      统一质量与来源门控
             ↓
  ┌──────────┼─────────────┐
  │          │             │
跟读评估域  场景沟通评估域  阶段临床评估域
  │          │             │
分项证据    整段对话证据     量表与人工记录
  └──────────┼─────────────┘
             ↓
      canonical evaluation run
             ↓
  患者反馈 / 治疗师复核 / 画像准入 / 趋势
```

三个域不能互相替代：

- 跟读表现较好不等于功能沟通已达成；
- 场景目标达成不等于构音清晰或语速正常；
- 日常自动趋势不等于 WAB/CADL 阶段性变化。

## 4. 统一评估运行契约

建议新增 canonical 层，避免继续把所有含义塞入 `AttemptEvaluation`。首选新增：

### 4.1 `evaluation_runs`

| 字段 | 含义 |
| --- | --- |
| `id` | 评估运行 ID |
| `patient_profile_id` | 患者档案 |
| `domain` | `repeat` / `functional_communication` / `clinical_stage` |
| `source_type` | `attempt` / `dialogue_session` / `assessment_session` |
| `source_id` | 对应来源 ID |
| `algorithm_version` | 如 `repeat-eval-v3.0` |
| `config_snapshot` | 阈值、权重、参考范围、特征开关的完整快照 |
| `input_provenance` | ASR、声学、SOE、LLM、契约及模型版本 |
| `quality_gate` | 质量判定、失败原因、可用范围 |
| `result_status` | `formal` / `provisional` / `review_required` / `unscorable` |
| `profile_eligibility` | 是否可进入画像及原因 |
| `adoption_status` | `candidate` / `adopted` / `superseded` |
| `supersedes_run_id` | 人工修订或重算时指向被替代版本 |
| `created_at` | 运行时间 |

同一来源允许有多个版本化 run，但只有一个 `adopted` 结果供画像消费。历史结果不得原地覆盖。

### 4.2 `evaluation_dimension_results`

| 字段 | 含义 |
| --- | --- |
| `evaluation_run_id` | 所属 run |
| `dimension_code` | 稳定的维度编码 |
| `value` | 数值，可空 |
| `level` | 类别结果，可空 |
| `unit` | 明确单位，如 `%`、`char/min`、`dBFS` |
| `status` | `measured` / `not_observed` / `unavailable` / `not_applicable` |
| `measurement_quality` | 本次测量质量，不叫泛化的 confidence |
| `evidence_snapshot` | 证据、位置、回合、原话、时间段 |
| `limitations` | 本维度限制 |

### 4.3 `evaluation_review_revisions`

以追加方式保存：

- 被修订的 run 和维度；
- 自动原值；
- 修订值或修订证据；
- `confirmed/corrected/unjudgeable`；
- 原因、治疗师、时间；
- 重算生成的新 run ID。

人工修订不得只改最终总分。应先修订证据或维度，再由同一版本规则确定性重算。

## 5. 统一质量门控

### 5.1 四级结果状态

| 状态 | 可给患者反馈 | 可进入个人趋势 | 可进入画像 | 可驱动调难 |
| --- | ---: | ---: | ---: | ---: |
| `formal` | 是 | 是 | 是 | 是，仍受策略门控 |
| `provisional` | 是，标明待确认 | 可单独展示 | 默认否 | 否 |
| `review_required` | 仅过程提示 | 否 | 人工确认后才可 | 否 |
| `unscorable` | 只显示重录/故障原因 | 否 | 否 | 否 |

### 5.2 硬门控

满足任一项时不得生成正式结果：

- 录音为空、有效发声过短、明显过轻、噪声过高或严重削波；
- ASR 为 mock、fallback 或失败；
- 正式依赖的 Provider 为 mock；
- 任务模板、场景契约或量表版本缺失；
- 输入单位不明或与算法配置不一致；
- 结构化语义输出不符合 Schema；
- 场景证据引用无法定位到患者原话；
- 算法版本或配置快照缺失；
- 关键维度不可用且当前算法没有明确的缺失处理规则。

### 5.3 软门控

以下情况通常为 `provisional` 或 `review_required`：

- ASR 未提供词级置信度，且关键内容对转写误差敏感；
- SOE、韵律或 LLM 结果可用但尚处 E1；
- 场景关键信息单元的最低证据置信度低于校准阈值；
- 设备或环境与历史记录不可比；
- 结果与最近稳定状态出现异常大偏差；
- 治疗师明确要求复核该类任务。

## 6. 跟读评估域 V3

### 6.1 正式维度

| 维度编码 | 含义 | 当前证据 | V3 边界 |
| --- | --- | --- | --- |
| `content_reproduction` | 目标内容复现 | 字符/词对齐、遗漏/替换/添加 | 受 ASR 误差影响，不叫构音准确性 |
| `articulation_evidence` | 构音、音节、声调证据 | SOE 分段 + 治疗师修订 | 校准前为 shadow/provisional |
| `fluency_efficiency` | 连续表达效率 | 表达速率、发音速率、停顿比例 | 不单纯追求更快 |
| `disfluency_events` | 重复、插入语、自我修正、长停顿 | 规则事件及时间位置 | 自我修正不一律视为负面错误 |
| `voice_state` | 相对响度、稳定性、F0/有声比例等 | 本地声学、韵律 | 未校准设备下仅作相对/描述性证据 |
| `independence` | 提示、求助、启动延迟 | 行为事件 | 扣分阈值为工程初值，需校准 |

### 6.2 内容复现

保留当前对齐事件，但输出命名调整：

```text
content_reproduction_rate
omission_count / positions
substitution_count / positions
addition_count / positions
alignment_algorithm_version
asr_text
target_text_snapshot
```

禁止把 ASR 对齐差异直接写成“发音错误”。出现低 ASR 可信度、方言或疑似可懂度问题时，标记为“转写与目标不一致，需听音复核”。

### 6.3 流利效率

同时保留：

- `expression_rate = 有效交流字符数 / 整段任务时长`；
- `articulation_rate = 有效交流字符数 / 有效发声时长`；
- `pause_ratio`、`longest_pause`、超过 1 秒/3 秒停顿；
- 有效字符的排除规则和算法版本。

V3 不把 180～240 视为普遍“正常范围”。在完成校准前，它只能是 `engineering_reference`，患者反馈优先使用个人基线和同任务变化。

### 6.4 声音状态与单位

内部正式存储统一使用 `dBFS`。未经真实声级计和设备校准的 `loudness_dba = dBFS + offset` 只能作为质量门控的工程派生量，必须保存校准偏移和设备信息，不得显示为临床 dBA。

V3 配置不得再出现无单位的 `60`、`69`。配置示例：

```json
{
  "metric": "active_loudness_dbfs",
  "unit": "dBFS",
  "engineering_reference": {"min": -35, "max": -12},
  "calibration_status": "uncalibrated_engineering_reference"
}
```

### 6.5 精细发音的 shadow 规则

- SOE 失败或 disabled 时结果为 `unavailable`，不是 0 分；
- coverage 只描述证据覆盖，不代表临床可信度；
- `intelligibility_proxy` 必须继续叫“代理指标”；
- 自动分段和声调结果允许治疗师追加修订，原始 Provider 输出只读；
- 在 E2 前不进入患者正式总分和自动调难；
- 若生成 shadow composite，缺失维度不得直接按 0 计算；应返回每维状态和覆盖率，是否归一化必须由版本化配置明确规定。

### 6.6 跟读综合结果

患者端默认不突出单一 overall score。建议展示：

1. 本次目标内容完成情况；
2. 一个最清晰的过程证据；
3. 独立完成程度；
4. 下一次只关注一个训练目标。

治疗师端可以查看 V3 composite，但必须同时展示权重、缺失维度、版本、measurement quality 和限制。V2 的 45/15/25/10/5 权重只作为回放基线，不自动继承为 V3 正式权重。

## 7. 功能性场景沟通评估域 V3

### 7.1 评价对象

评价对象是完整 `ScenarioDialogueSession`，不是单句 Attempt。正式维度：

| 维度 | 说明 | 证据 |
| --- | --- | --- |
| `goal_achievement` | 最终是否让对方拥有采取行动所需信息 | 契约要求 + 整段证据 |
| `information_sufficiency` | 必需信息单元的完成情况 | 逐条信息单元及原话/回合 |
| `response_ability` | 是否回应当前问题、确认或澄清 | 当前问题与下一患者回合 |
| `relevance_organization` | 是否围绕情境并基本组织可理解 | 独立证据，不再复用信息单元计数 |
| `independence` | 提示、求助和启动支持 | 会话级提示轨迹 |
| `repair_ability` | 真实误解/追问后能否补充或改述 | 仅真实 repair 回合 |

### 7.2 证据抽取与规则层边界

LLM 可以：

- 从患者原话抽取信息单元；
- 判断是否回应当前问题并引用证据；
- 对相关性/组织提供结构化观察；
- 生成受约束的患者反馈文案。

LLM 不可以：

- 修改沟通目标、必需信息或结束条件；
- 直接给最终总分；
- 在无原话证据时补全信息；
- 把模型置信度冒充临床置信度；
- 在没有 repair 回合时推断修复能力。

### 7.3 缺失维度处理

`repair_ability=not_observed` 时不记 0 分。若专业端需要 composite，应从分母移除该维度并按已观察维度归一化，且保存实际生效权重。患者端只显示“本次未观察到沟通修复机会”。

### 7.4 治疗师复核后重算

复核流程必须改为：

```text
自动 evidence_snapshot
  → 治疗师确认/增删/标不确定
  → 新 evidence revision
  → scenario-dialogue-rules-v3 确定性重算
  → 新 evaluation_run supersedes 旧 run
```

`evidence_overrides` 不得仅作为旁路 JSON 存放。最终 adopted run 必须说明采用自动证据还是人工修订证据。

### 7.5 历史单题场景

- 冻结新增患者任务；
- 保留历史结果和录音只读；
- 不与多轮场景趋势合并；
- 不进入画像 V2，除非治疗师明确将其迁移为人工证据；
- 旧 `scenario-information-units-v1` 仅用于兼容展示。

## 8. 阶段临床评估域

WAB、CADL、人工可懂度和接受度必须与日常自动评估分开。

建议扩展 `AssessmentSession` 或新增量表结构，至少保存：

- `instrument_name`、`instrument_version`、语言/本地化版本；
- 评估阶段和日期；
- 施测者及角色；
- 原始条目、分量表、总分、缺失条目；
- 设备、环境、是否远程、用时；
- 是否偏离标准施测流程及原因；
- 人工复核状态；
- 与哪一次基线可比以及不可比原因。

前后测比较只能在量表版本和必要施测条件兼容时生成。默认输出变化量和事实描述；没有预先确认的阈值时，不输出“显著改善”“达到临床意义”等表述。

## 9. 术语与置信度拆分

V3 禁止继续使用一个 `confidence` 表示所有可信程度。按以下语义拆分：

- `provider_confidence`：外部模型原始置信度；
- `measurement_quality`：本次输入和测量质量；
- `evidence_confidence`：某条结构化证据的模型/规则把握度；
- `evidence_sufficiency`：画像支持是否充足；
- `review_status`：是否经过人工复核；
- `calibration_level`：算法 E0～E4 成熟度。

这些字段不可互换，也不能简单相乘生成一个看似精确的总置信度。

## 10. 版本与配置

每次运行必须固定：

- 算法版本；
- 特征提取版本；
- 阈值和权重快照；
- 任务/契约/量表版本；
- Provider、模型、Prompt 版本；
- 单位和设备/校准信息；
- 缺失维度处理方式；
- 结果准入状态。

版本建议：

```text
repeat-eval-v3.0
functional-communication-v3.0
clinical-stage-v2.0
pronunciation-shadow-v1.x
```

算法升级不得改写旧 run。需要重算时生成新 run，并保留 `supersedes_run_id` 和差异报告。

## 11. API 目标

建议新增稳定读取接口：

- `GET /evaluation-runs/{id}`：完整专业结果；
- `GET /attempts/{id}/evaluation-v3`：跟读 V3；
- `GET /scenario-dialogues/{id}/evaluation-v3`：场景 V3；
- `POST /evaluation-runs/{id}/reviews`：追加复核；
- `POST /evaluation-runs/{id}/recompute`：基于修订证据重算；
- `GET /patients/{id}/evaluation-timeline?domain=`：分域趋势；
- `GET /assessment-sessions/{id}`：阶段评估及可比性状态。

所有返回值应包含 `result_status`、`profile_eligibility`、`algorithm_version`、`limitations` 和 adopted/review 状态。

## 12. 实施顺序

### V3.0：质量与单位基线

- 修复推荐和家属视图中的 dBA/dBFS 混用；
- 为旧结果补充单位解释和算法版本；
- 建立正式/provisional/review_required/unscorable 状态；
- 为质量门控、单位一致性和 mock 隔离补测试。

### V3.1：跟读 canonical run

- 从现有 `rehab-process-v2` 映射到 V3 分项；
- 拆分内容复现、流利效率、事件、声音、独立性；
- 精细发音保持 shadow；
- 双写 V2/V3，比较固定回归集。

### V3.2：多轮场景 canonical run

- 分离 response 与 relevance 证据；
- 实现 repair 未观察时的缺失处理；
- 实现人工修订后的确定性重算；
- 冻结旧单题场景新增入口。

### V3.3：阶段评估扩展

- 扩展量表版本、条目、施测条件和可比性；

## 13. 测试矩阵

### 13.1 必须新增的自动测试

- 所有单位字段与策略配置单位一致；
- dBFS 真实值不会进入旧 60/69 分支；
- mock、fallback、低质量和未知算法版本均不可进入画像；
- 同一输入与配置产生相同 run；
- 不可用维度不按 0 参与总分；
- repair 未观察时为 null/not_observed，并正确归一化；
- response 与 relevance 使用不同证据；
- 治疗师修订会生成新 run，旧 run 不被覆盖；
- 新 run 能完整指出 superseded 版本；
- 历史单题场景不进入新趋势；
- 不同量表版本默认不可直接比较；
- 患者接口不泄露 Provider 原始敏感数据和治疗师审计详情。

### 13.2 固定回归样本

至少覆盖：

- 完整跟读、遗漏、替换、添加；
- 插入语、词/短语重复、自我修正；
- 长静默后快速说完与持续慢速表达；
- 过短、过轻、噪声、削波、ASR 故障；
- 方言/同音导致 ASR 不稳的复核样本；
- 场景完整达成、部分达成、无关回答；
- 同义表达、模糊表达、提示后完成；
- 真实澄清成功/失败、未安排修复；
- LLM 非法 JSON、虚构引用、低置信度；
- WAB/CADL 同版本与不同版本比较。

## 14. V3 完成标准

V3 只有同时满足以下条件才可替代 V2 主链路：

1. 三个评估域的数据、展示和趋势完全分开；
2. 每个维度都有来源、单位、状态、证据、版本和限制；
3. 无效证据不生成正式 run；
4. 人工修订通过新 run 重算，不覆盖原始结果；
5. 发音 shadow 缺失不按 0，且不驱动正式调难；
6. 场景 response、relevance、repair 具有独立证据；
7. 历史 V2 可读、可对照、可回滚；
8. 固定回归集、边界测试和迁移测试通过；
9. 画像 V2 只消费 adopted 且 profile-eligible 的 V3 结果；
10. 对外界面不把工程参考值和未经校准的模型结果描述为临床标准。
