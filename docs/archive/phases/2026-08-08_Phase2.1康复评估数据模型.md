# 2026-08-08 Phase 2.1 康复评估数据模型

## 本次任务

根据 Phase 2 目标，优先建立符合言语康复专业逻辑的康复评估数据模型。

本阶段只实现 Phase 2.1，不实现过程性监控自动计算、训练反馈改造、阶段性 assessment、前端图表展示。

## 设计方案

新增独立后端模块：

```text
backend/app/modules/evaluations/
├── router.py
├── service.py
├── model.py
└── schema.py
```

设计思路：

- `evaluation_metrics` 作为康复评价指标字典。
- `attempt_evaluations` 保存每一次 attempt 产生的结构化指标值。
- `evaluation_source` 保留 `mock_ai`、`human`、`clinician`，为后续人工评价和治疗师评价预留入口。
- 过程性指标和长期效果指标都先统一登记在指标字典中，Phase 2.2 和 Phase 2.4 再分别写入真实业务逻辑。

### 5. 人工评价保存测试

需要先有一个 `attempt_id`。可以通过正常训练流程创建一次 attempt，也可以从前端训练完成后的接口响应中复制。

在 Swagger 中调用：

```text
POST /api/evaluations/attempts/{attempt_id}
```

请求体：

```json
{
  "items": [
    {
      "metric_name": "script_accuracy",
      "value": 95,
      "evaluation_source": "human"
    },
    {
      "metric_name": "error_count",
      "value": 2,
      "evaluation_source": "human"
    }
  ]
}
```

预期结果：

- HTTP 状态为 200。
- 返回 `code: 0`。
- `items` 中能看到保存的 `script_accuracy` 和 `error_count`。
- `evaluation_source` 为 `human`。

继续调用：

```text
GET /api/evaluations/attempts/{attempt_id}
```

预期结果：

- 能查到刚才保存的人工评价指标。
- `metric_category` 为 `process`。
- `value` 与手动提交值一致。

### 6. 重复提交测试

再次调用同一个：

```text
POST /api/evaluations/attempts/{attempt_id}
```

请求体改为：

```json
{
  "items": [
    {
      "metric_name": "script_accuracy",
      "value": 88,
      "evaluation_source": "human"
    }
  ]
}
```

预期结果：

- 不会新增重复的 `human + script_accuracy` 记录。
- 再次 GET 查询时，`script_accuracy` 的值应更新为 `88`。

这是为了验证 `attempt_id + metric_id + evaluation_source` 的唯一约束和幂等更新逻辑。

### 7. 权限与异常测试

可以手工检查：

1. 未登录时调用 `GET /api/evaluations/metrics`，预期返回 401 或未认证错误。
2. 使用不存在的 `attempt_id` 调用保存接口，预期返回“作答不存在”。
3. 使用不存在的 `metric_name`，预期返回“评价指标不存在”。
4. 使用其他用户的 `attempt_id`，预期不能读取或写入。
