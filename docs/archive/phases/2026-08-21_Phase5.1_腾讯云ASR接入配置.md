# Phase 5.1 腾讯云 ASR Provider 接入配置

## 接入选择

当前项目采用：

- 类型：服务端
- 平台/语言：Python
- 腾讯云能力：一句话识别 `SentenceRecognition`

患者端仍只负责录音与上传，腾讯云密钥只保存在后端环境变量中，避免暴露到浏览器。

## 本地依赖

后端 `requirements.txt` 已加入：

```txt
tencentcloud-sdk-python-common>=3.0.0
tencentcloud-sdk-python-asr>=3.0.0
```

安装方式：

```bash
cd backend
pip install -r requirements.txt
```

## 环境变量

在 `backend/.env` 中填写：

```env
ASR_PROVIDER=tencent
TENCENTCLOUD_SECRET_ID=你的 SecretId
TENCENTCLOUD_SECRET_KEY=你的 SecretKey
TENCENT_ASR_APP_ID=可选，先留空也可以
TENCENT_ASR_REGION=ap-guangzhou
TENCENT_ASR_ENGINE_MODEL_TYPE=16k_zh
TENCENT_ASR_VOICE_FORMAT=ogg-opus
```

如需回到本地 mock：

```env
ASR_PROVIDER=mock
```

## 音频格式约束

腾讯云一句话识别适合短音频，当前后端限制为 3MB 以内。前端录音已优先使用 `audio/ogg;codecs=opus`，上传文件名会按真实 MIME 类型保存为 `.ogg` 或 `.webm`。

如果浏览器不支持 `ogg-opus`，会 fallback 到 `webm`。这种情况下腾讯云可能无法识别，后续可以通过后端转码或改接录音文件识别来收口。

## 数据口径

ASR 接入后，评分流程继续沿用当前字段：

- `asr_text`
- `acoustic_metrics`
- `semantic_metrics`
- `raw_model_output`

因此患者端、家属端、治疗师端的训练记录和趋势展示不需要因为 ASR provider 改动而重构。

## 验证路径

1. 后端安装依赖并启动。
2. `.env` 填入腾讯云密钥，设置 `ASR_PROVIDER=tencent`。
3. 患者端完成一次短音频训练。
4. 点击分析后，训练记录中的 `asr_text` 应显示腾讯云真实转写文本。
5. 如需排查，可先改回 `ASR_PROVIDER=mock` 确认基础流程仍正常。
