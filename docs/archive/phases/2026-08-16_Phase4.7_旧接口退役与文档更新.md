# Phase 4.7 旧接口退役与文档更新

日期：2026-08-16

## 收口目标

Phase 4.7 不删除历史表，不破坏迁移链，采用软退役方式把 Phase 3 中偏重的推荐复核流退出主路径。

当前推荐主路径明确为：

```text
能力画像
-> 策略配置
-> 趋势归因
-> 自适应推荐
-> 患者任务组
-> 反馈回流
```

治疗师端职责保持为：

```text
查看训练记录
查看趋势与归因
必要时写自然语言调整说明
```

## Deprecated 接口

以下接口仍保留，但已标记为 deprecated：

```text
POST /api/therapist/patients/{patient_user_id}/training-recommendation/review
POST /api/therapist/patients/{patient_user_id}/training-recommendation/strategy-feedback
```

退役原因：

- 它们容易让新开发者误以为治疗师需要审批每次推荐。
- 当前推荐已由 `recommendation_policy` 负责策略判断、趋势归因和自适应调整。
- 治疗师自然语言干预已收敛到 `recommendation-note`。

## 保留的历史表

以下表暂不删除：

```text
training_recommendation_reviews
recommendation_strategy_feedbacks
```

保留原因：

- 兼容历史演示数据。
- 避免破坏现有迁移链。
- `recommendation_strategy_feedbacks` 当前仍承载 `manual_note` 兼容用途。

后续如果进入正式产品化，可再拆出更清晰的：

```text
therapist_recommendation_notes
```

## 当前主接口

患者端：

```text
GET  /api/training/today
GET  /api/training/recommendation
POST /api/training/session
POST /api/attempts/{attempt_id}/analyze
```

治疗师端：

```text
GET  /api/therapist/patients
GET  /api/therapist/patients/{patient_user_id}/training-records
GET  /api/therapist/patients/{patient_user_id}/training-trends
GET  /api/therapist/patients/{patient_user_id}/training-recommendation
GET  /api/therapist/patients/{patient_user_id}/training-recommendation/effects
GET  /api/therapist/patients/{patient_user_id}/recommendation-note
POST /api/therapist/patients/{patient_user_id}/recommendation-note
```

家属端：

```text
GET /api/family/patients
GET /api/family/observation?patient_user_id=...
```
