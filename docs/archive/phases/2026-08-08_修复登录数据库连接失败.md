# 2026-08-08 修复登录数据库连接失败

## 本次问题

本地 PostgreSQL 已配置完成，但网页登录时后端在访问数据库阶段失败。

排查后确认问题不止一个：

1. FastAPI 运行配置没有自动读取 `backend/.env`。
2. Alembic `env.py` 依赖 `python-dotenv`，但运行环境可能未安装该包。
3. Alembic `target_metadata = Base.metadata` 被注释吞掉，存在迁移元数据不可用风险。
4. SQLAlchemy 模型存在导入顺序问题，登录时首次查询 `User` 可能触发 mapper 配置失败。
5. `passlib==1.7.4` 与最新 `bcrypt==5.x` 不兼容，注册/登录密码哈希阶段会失败。

## 本次改动

### 1. 修复 FastAPI `.env` 加载

修改：

```text
backend/app/core/config.py
```

新增轻量 `.env` 加载函数：

```python
load_env_file(backend_dir / ".env")
```

现在 FastAPI 启动时会自动读取：

```text
backend/.env
```

不再依赖必须手动在 PowerShell 中设置 `DATABASE_URL`。

### 2. 修复 Alembic 环境配置

修改：

```text
backend/migrations/env.py
```

改动：

- 移除对 `python-dotenv` 的强依赖
- 使用项目内置 `.env` 加载逻辑
- 修复 `target_metadata = Base.metadata`
- 保证 Alembic 能正确读取 `DATABASE_URL`

### 3. 修复 SQLAlchemy 模型导入顺序

修改：

```text
backend/app/modules/users/model.py
backend/app/modules/agents/model.py
```

修复点：

- 将 `PatientProfile -> Agent` 的关系绑定放到类定义之后
- 在 `agents/model.py` 显式导入 `FileAsset`
- 避免登录时因为只查询用户表而触发 `Agent` / `FileAsset` 尚未加载的 mapper 错误

### 4. 固定 bcrypt 兼容版本

修改：

```text
backend/requirements.txt
```

新增：

```text
bcrypt==4.0.1
```

原因：

`passlib==1.7.4` 与 `bcrypt==5.x` 不兼容，会在密码哈希阶段报错。

## 注意事项

如果仍然无法登录，请确认：

1. 后端服务已经重启，不能继续使用旧进程。
2. `backend/.env` 中的 `DATABASE_URL` 指向当前 PostgreSQL。
3. 已重新执行：

```powershell
python -m pip install -r requirements.txt
python -m alembic upgrade head
```

4. 浏览器前端请求的后端地址仍为：

```text
http://127.0.0.1:8000
```
