# Phase 4 推荐任务组纠偏记录

日期：2026-08-15

## 背景

患者端训练入口仍然表现为“推荐一个最合适任务 + 两个旧样例入口”，这和 Phase 4 的训练内容库方向不一致。患者每天更需要一组清晰、可完成、由易到难的任务，而不是在单项任务里反复选择。

## 本次调整

1. 推荐结果从单个 `task_template` 扩展为 `task_sequence`。
2. 默认生成 3 步任务组：
   - 热身：比当前能力略简单，优先使用跟读短句。
   - 主练：匹配当前画像与推荐类型。
   - 挑战：不低于当前能力，略提升内容或自主表达难度。
3. 患者端首页与进入训练页改为展示“今日任务组”，旧的跟读/场景卡片保留为自选备用入口，不再标记为推荐。
4. 患者开始推荐训练时，会把整组任务 ID 带入训练会话，后端一次创建多个 `SessionTask`。
5. 训练会话前端按顺序完成每一项，只有全部任务完成后才生成最终反馈页。
6. 后端内容库补充 L5 跟读挑战任务，避免 L4 患者的“挑战项”回退到更简单任务。

## 当前推荐示例

以 `admin` 患者当前画像为例，推荐任务组为：

1. 连贯短句：散步（L3/S2）
2. 复合短句：复诊（L4/S2）
3. 挑战短句：复健安排（L5/S3）

## 设计原则

患者端只呈现“今天练什么、为什么练、按什么顺序练”。专业指标仍留在治疗师端和系统内部，患者端避免出现过多 WAB/CADL 等量表语言。

治疗师确认或调整过的推荐仍可影响患者端任务方向；没有治疗师复核时，患者端使用系统画像算法生成的任务组。

## 后续微调方向

1. 根据人工测试反馈调整每组任务数量，可从 3 项扩展到 4-5 项。
2. 为不同障碍类型增加更细的内容标签，例如命名、复述、问答、生活请求、情绪表达。
3. 在任务完成后给患者显示“本组完成情况”，而不是只展示单次录音反馈。
4. 把推荐任务组生成规则独立成策略模块，便于后续接入更正式的算法或 LLM 推荐。
