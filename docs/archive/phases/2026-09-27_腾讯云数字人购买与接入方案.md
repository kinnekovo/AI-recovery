# 腾讯云数字人购买与接入方案

> 日期：2026-09-27  
> 适用产品：言语康复智能体患者端  
> 当前结论：采用腾讯云智能数智人的 **2D 小样本照片（标准版）+ 会话互动并发（云渲染）**，先按月购买 1 路验证，保留现有本地 2.5D 形象作为故障与并发兜底。

## 1. 先给结论

患者上传一张照片，生成自己的个性化数字人；训练时，系统继续使用现有的 ASR、康复对话/规则、评估和 TTS，腾讯云只负责把已有 TTS 音频实时驱动成数字人视频流。

推荐采购组合：

| 项目 | 数量 | 单价 | 用途 |
| --- | ---: | ---: | --- |
| 2D 小样本照片形象 | 首期 1 个 | 19.9 元/个 | 从一张照片训练个性化形象，照片形象永久有效 |
| 会话互动并发（云渲染）- 2D 小样本照片 | 1 路 | 3,500 元/月/路 | 同时允许 1 名患者进行实时数字人训练 |
| 现有 TTS、ASR、对话与评估服务 | 复用 | 不新增数字人侧费用 | 语音合成、识别、对话和康复评价 |
| 本地 2.5D 形象 | 保留 | 0 元新增费用 | 并发占满、网络异常或服务故障时兜底 |

首月定制形象试点预算为 **3,519.9 元**。试点通过后再改买年包：1 路 **27,000 元/年**；如果有 100 个患者分别定制照片形象，首年数字人侧名义价格为 `100 × 19.9 + 27,000 = 28,990 元`。每增加 1 个同时在线训练名额，再增加 1 路并发。

采购前必须通过工单或商务书面确认：同一条“2D 小样本照片”并发能否在不同患者的 `AssetVirtualmanKey` 之间轮换使用，以及 WebRTC/TRTC/流量是否另行计费。价格页把并发定义为同时在线建流数量，但没有明确写出一条并发能轮换多少个照片资产。

## 3. 购买方案

### 3.1 阶段 A：低成本技术预验证

腾讯产品页目前展示“交互数智人-特惠体验包”：2D 精品、1 路并发、140 元/天。建议先购买 1～3 天，只验证 H5 SDK、建流、音频驱动、打断、移动端播放和会话关闭，预算 140～420 元。

注意：该体验包标注的是“2D 精品”，不是“2D 小样本照片”。不同形象类型的互动并发不能混用，因此它只能验证技术链路，不能替代照片形象正式验收。

### 3.2 阶段 B：个性化照片形象试点

收到腾讯书面确认后购买：

- 1 个“2D 小样本照片”形象配额：19.9 元。
- 1 路“会话互动并发（云渲染）- 2D 小样本照片”月包：3,500 元/月。
- 先用 1 张已取得授权的内部测试照片训练和验收。
- 不购买声音复刻：当前产品已有 TTS，直接使用 `DriverType=3` 原声音频驱动。
- 不购买视频播报小时包：训练是实时会话，不是离线视频生成。
- 不购买 iPaaS：目前只需 SDK/API 集成，不需要嵌入腾讯的管理页面。

### 3.3 阶段 C：正式运行

月包试点通过后再购买年包：

- 1 路：27,000 元/年，适合早期小规模试用。
- N 路：`27,000 × N 元/年`，N 等于希望同时训练的患者人数。
- 每个患者个性化照片形象：19.9 元/人，一次性；当前价格指南注明照片形象永久有效。
- 不为低频患者永久占用会话：进入训练时申请并发，离开页面立即关闭会话并释放。

如果实际同时在线比例较低，1 路并发配合排队提示和本地 2.5D 降级即可覆盖首期。不要按注册患者总数采购并发。

### 3.4 不要买错的 SKU

- 不要买“2D 小样本免训练（照片素材）”：它只支持视频制作，不支持会话交互。
- 不要把“2D 小样本照片-轻量版”当作标准云渲染版本；轻量版走端渲染能力，采购和接入路径不同。
- 不要买 2D 端渲染按应用年包：价格为 800,000 元/年，不适合当前 Web MVP。
- 不要买 2D 精品定制：价格为 350,000 元/个，远超个性化照片方案。
- 不要买音视频播报小时包、音视频播报并发：它们面向离线视频制作，不是本项目的实时训练会话。
- 不要让体验包直接转生产：体验包形象类型可能与正式照片形象并发不兼容。

### 3.5 下单前工单问题清单

将以下问题原样提交腾讯云工单，并保留书面答复：

1. “2D 小样本照片 19.9 元/个”与“会话互动并发（云渲染）-2D 小样本照片 3,500 元/月/路”是否为本场景的完整兼容组合？
2. 1 路并发是否可以在不同时段轮换驱动多个患者的 `AssetVirtualmanKey`，是否存在资产数量上限？
3. WebRTC 拉流、腾讯云直播或 TRTC 是否有额外流量、时长、带宽或 MAU 费用？
4. H5 SDK 公有云 `sign` 的生成算法、有效期和刷新方式是什么？能否保证前端不暴露 `AccessToken`？
5. 照片、训练资产、音频和日志存储在哪个地域，保留多久，如何删除和导出？
6. 2D 小样本照片及云渲染服务的下线通知周期、SLA 和退款/迁移规则是什么？
7. 患者属于医疗健康场景时，用户授权模板、未成年人/监护人授权和数据合规还有哪些额外要求？

## 4. 推荐系统架构

```text
患者浏览器
  ├─ 麦克风录音 ─→ 现有 ASR ─→ 康复对话/规则/LLM ─→ 训练反馈与评估
  ├─ 腾讯 H5 SDK ←─ 短期 sign + AssetVirtualmanKey ── 本项目后端会话代理
  └─ 数字人视频流 ←──────────── 腾讯云云渲染
                                      ↑
现有 TTS ─→ 后端转 PCM 16k/16bit/mono ─→ 浏览器分片 ─→ 音频驱动

异常或并发满：自动切换现有 Local2_5DProvider，训练流程仍可继续
```

核心原则：

- 腾讯云只承担“形象训练 + 实时视频渲染”，不替换现有康复业务、ASR、LLM、评估和 TTS。
- 每位患者绑定自己的 `AssetVirtualmanKey`；会话采用资产模式 `createSessionByAsset`，不使用固定项目形象模式。
- `AppKey` 和 `AccessToken` 只存后端密钥管理；浏览器只拿短期 `sign`、资产 Key 和租约信息。
- 所有云会话通过本项目后端统一租赁、续租、关闭和审计，不能由前端直接持有长期凭证。

## 5. 接入方案

### 5.1 控制台与资产流程

第一阶段先在腾讯数智人平台人工完成：

1. 购买照片形象配额和对应云渲染并发。
2. 上传取得明确授权的测试照片，完成授权审核和训练。
3. 在“资产管理 > 形象资产”取得 `AssetVirtualmanKey`。
4. 取得项目 `AppKey`、`AccessToken`，只配置到后端环境变量。
5. 用官方 Demo 建一次资产会话，验证账号和资源正确，再开始接入产品。

试点期间不要先开发自动提交照片训练 API。等资产质量、审核周期、用户授权和删除流程验证清楚后，再把患者上传和自动训练接入产品。

### 5.2 后端改造

建议新增 `TencentCloudAvatarProvider`，继续复用现有 `/api/avatar/sessions` 会话代理和租约模型：

- 配置项：`TENCENT_AVATAR_ENABLED`、`TENCENT_AVATAR_APP_KEY`、`TENCENT_AVATAR_ACCESS_TOKEN`、API/WS 地址、默认协议和驱动类型。
- `POST /api/avatar/sessions`：校验患者与形象资产绑定，原子申请并发租约，生成 H5 `sign`，返回短期启动信息。
- `POST /api/avatar/sessions/{id}/heartbeat`：刷新本地租约；异常断线时让租约自动过期。
- `DELETE /api/avatar/sessions/{id}`：调用腾讯关闭会话接口，释放并发，然后释放本地租约。
- `GET /api/avatar/sessions/capacity`：返回总路数、占用数和是否需要降级，便于患者端提示。
- 把患者和腾讯资产的映射单独建表，至少保存 `patient_id`、`asset_virtualman_key`、状态、授权记录、创建时间和删除状态；不要把照片或令牌写入日志。
- 对腾讯的 `LimitExceeded`、超时、建流失败和 5xx 分类处理；能降级的错误直接切本地形象，不阻断训练。

音频适配建议放在后端：把现有 TTS 结果统一转为 `PCM / 16kHz / 16bit / 单声道`，向前端返回受鉴权保护的 PCM 流或短时下载地址。这样不同浏览器不需要自行重采样，行为更一致。

### 5.3 前端改造

在现有 Avatar Provider 抽象下新增 `TencentCloudAvatarProvider`：

- `connect()`：向后端申请租约，使用 `sign + assetVirtualmanKey` 初始化 H5 SDK，再调用 `createSessionByAsset({ driverType: 3, userId, ... })` 和 `startSession()`。
- `speak()`：获取 PCM 音频，切片并 Base64 编码，通过 `IVH.play({ command: 'audio', data, seq, isFinal })` 发送。
- `stop()`：收到 `AudioStart` 后才允许打断；调用 SDK `stop()` 后等待 `AudioOver`，再开始下一次播报或开放麦克风。
- `dispose()`：页面离开、刷新、超时和异常时都调用关闭会话，并释放后端租约。
- 监听 `canplay`、`socketStatus`、`socket`、`error`；首帧超时、WebSocket 断开或并发满时切到 `Local2_5DProvider`。
- 浏览器自动播放受限时，使用“开始训练”按钮作为用户手势，再初始化视频和音频。

建议首期选 H5 SDK + WebRTC，以减少自建播放器和房间逻辑；如果正式环境需要 TRTC，再使用自有 TRTC AppId 并单独核对其计费。

### 5.4 音频驱动协议要点

- 建会话使用 `DriverType=3`，即原声音频驱动。
- 音频只能是 PCM、16kHz、16bit、单声道。
- `Seq` 从 1 开始，同一段音频递增。
- 最后必须发送一个空 `Audio` 且 `IsFinal=true` 的尾包，让数字人回到静默状态。
- 官方实践建议按 5120 字节（约 160ms）分片发送；离线音频可约每 120ms 推送一片，实时麦克风音频可收到后立即发送。
- 使用 H5 SDK 5.5.0 或更高版本，才能对音频驱动执行打断。
- 录音开始前先停止数字人播报，收到 `AudioOver` 后再开启麦克风，避免数字人声音被 ASR 误识别成患者输入。

### 5.5 一次训练的时序

1. 患者点击“开始训练”，前端向后端申请数字人并发租约。
2. 后端返回短期 `sign`、患者形象 Key 和租约；前端建流并等待 `canplay`。
3. 训练提示由现有业务生成，现有 TTS 合成音频。
4. 音频转为标准 PCM 后分片驱动数字人播报。
5. 患者准备回答时，前端打断播报并等到 `AudioOver`，再开启录音。
6. 录音进入现有 ASR、康复对话/规则和评估链路。
7. 新的 TTS 回复再次驱动数字人。
8. 训练结束或页面离开，关闭腾讯会话并释放并发；失败则切本地 2.5D，不丢失训练记录。

## 6. 验收标准

### 功能

- 同一患者每次训练都加载其绑定的照片形象，不串用其他患者资产。
- 数字人能播报现有 TTS 音频，口型与声音基本同步。
- 患者开始录音时能中断数字人，且数字人声音不会进入 ASR。
- 页面离开后腾讯会话确实关闭，并发立即或在可接受时间内恢复。
- 并发满、断网、腾讯异常时，训练自动降级到本地 2.5D。

### 安全与合规

- 前端包、网络请求、Sentry/日志中均无 `AccessToken`。
- 照片上传前展示用途、处理方、保存期限、删除方式并取得单独同意；撤回同意后能停用并删除资产。
- 患者 ID 与腾讯 `UserId` 使用不可逆或不可直接识别的内部标识，不传姓名、手机号、病历号。
- 图片、音频和调试日志不默认长期保存，不用于腾讯之外的训练用途。

### 性能与运维

- 记录建流成功率、首帧耗时、音频首包耗时、播报完成耗时、打断耗时、并发占满次数和降级率。
- 首期建议目标：建流成功率不低于 99%，首帧 P95 不高于 5 秒，打断 P95 不高于 500ms；最终阈值以真机试点数据调整。
- 后端每天巡检异常残留会话，发现本地租约已结束但腾讯仍在推流时主动关闭。

## 7. 两周落地顺序

### 第 1～2 天：采购前验证

- 提交工单问题，确认 SKU、资产轮换和附加费用。
- 购买 1～3 天体验包，跑通官方 H5 SDK Demo。
- 验证 WebRTC、移动端自动播放、音频驱动、打断和关闭会话。

### 第 3～5 天：后端接入

- 完成腾讯 Provider、签名、会话租约、关闭与错误映射。
- 完成 TTS 音频转 PCM 和受保护分发。
- 加入患者资产映射与审计字段。

### 第 6～8 天：前端接入

- 实现 Tencent Provider、H5 SDK 生命周期、音频分片与事件状态机。
- 接入现有训练页；实现本地 2.5D 自动降级。

### 第 9～10 天：照片形象试点

- 购买 1 个照片形象和 1 路照片云渲染月包。
- 使用授权测试照片完成资产训练并替换体验形象。
- 做 Chrome、Edge、Android、iOS 真机验证。

### 第 11～14 天：压测与小范围试用

- 验证单路并发排队、超时回收、重复登录、刷新/杀进程和弱网。
- 邀请少量内部用户试用；统计首帧、打断、降级和满意度。
- 达标后再决定年包和患者自助照片定制功能。

## 8. 决策门槛

满足以下条件才从月包转年包：

- 腾讯书面确认同一路可轮换多个患者照片资产，且无不可接受的附加流量费用。
- 试点患者认可照片形象质量，照片审核与删除流程可接受。
- 真机建流、打断和长会话稳定性达标。
- 本地 2.5D 降级可用，腾讯故障不会阻断康复训练。
- 已完成照片授权、隐私说明、未成年人监护授权和资产删除流程的合规审查。

如果上述任一项不满足，只保留短期月包，不签年包；继续使用本地 2.5D 或回到供应商选型阶段。
