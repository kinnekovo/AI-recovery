# 2026-08-08 Phase 2.2 过程性监控自动写入

## 本次任务

在 attempt 完成分析后，自动生成并保存 4 个过程性监控指标：

- script_accuracy
- error_count
- speech_rate
- loudness

本阶段只实现 Phase 2.2，不改训练完成后的前端展示结构，不新增 `/evaluation` 页面，不实现阶段性 WAB/CADL assessment。

## 设计方案

现有训练分析入口是：

```text
POST /api/attempts/{attempt_id}/analyze
```

Phase 2.2 继续使用该入口作为 attempt 完成分析的触发点。

新增声学分析适配层：

```text
backend/app/integrations/acoustic_analysis/
├── __init__.py
└── provider.py
```

MVP 阶段使用 `MockAcousticAnalysisProvider`，返回：

- speaking_duration_seconds
- loudness_dba
- long_pause_over_3s_count

后续可替换为真实 ASR、VAD、librosa、openSMILE 或云端声学分析服务。

## 本次主要改动

### 1. 新增声学分析 Mock Provider

新增：

```text
backend/app/integrations/acoustic_analysis/provider.py
```

用于隔离未来真实声学模型接入。

### 2. 新增 ProcessEvaluation Schema

更新：

```text
backend/app/modules/evaluations/schema.py
```

新增：

```text
ProcessEvaluation
```

包含：

- script_accuracy
- error_count
- speech_rate
- loudness
- details

### 3. 新增过程性评价生成与保存逻辑

更新：

```text
backend/app/modules/evaluations/service.py
```

新增：

- `generate_process_evaluation`
- `save_process_evaluation`

逻辑：

1. 根据任务目标文本统计脚本总字数。
2. 根据 ASR 转写与目标文本估算正确脚本字数比例。
3. 根据插入语、长停顿、难以理解发音、无意义重复估算错误数。
4. 根据有效交流字数和说话时间计算言语速率。
5. 从声学分析结果读取响度。
6. 将 4 个指标写入 `attempt_evaluations`，来源为 `mock_ai`。

### 4. 接入 analyze 流程

更新：

```text
backend/app/modules/scoring/service.py
```

现在调用：

```text
POST /api/attempts/{attempt_id}/analyze
```

成功后会同时完成：

1. Mock ASR。
2. Mock 声学分析。
3. Mock LLM 旧评分。
4. 保存 `attempt_analysis_results`。
5. 保存 `attempt_scores`。
6. 保存 `attempt_evaluations` 中的 4 个过程性指标。

如果旧 attempt 已经存在 `attempt_scores`，但还没有 `mock_ai` 过程性指标，再次调用 analyze 时会补写过程性指标。
