# V3.4 Calibration & Promotion

## Architecture
Calibration is an offline, append-only validation layer: canonical run dimension → frozen dataset sample → independent therapist annotations → explicit calibration run → metric decision. It is not read by training, Profile V2, Policy V2, or patient UI.

## Dataset and annotations
Datasets are draft/frozen/archived and uniquely versioned. Samples reference immutable canonical runs and a single dimension. Frozen datasets reject mutation. Annotations retain annotator, round, value, unit, comment and supersession reference; raw annotations are never overwritten. The write response does not disclose peer annotation values.

## Analysis and promotion
`promotion-policy-v1` is a versioned internal engineering validation policy, not a clinical standard. Patient-level seeded development/holdout split prevents patient leakage. Continuous analysis reports MAE, RMSE, bias, Pearson and Spearman separately. Reliability reports annotation-pair statistics and marks insufficient pairs `reference_unstable`. Subgroup output marks small groups `insufficient_sample`. Promotion returns structured decisions and reason codes; provider/model drift produces `provider_version_changed`.

## Registry and API
Metric registry statuses are experimental, shadow, provisional, promoted and suspended. Calibration runs snapshot split, policy, metrics and decision immutably. Professional-only APIs live under `/api/calibration` for datasets, samples, freeze, annotations, registry and explicit analysis runs. `python -m app.modules.calibration.run` is an offline-safe entry point and never implicitly analyzes production data.

## Validation and limitations
Migrations `0031_calibration_promotion` and `0032_calibration_adjudication` follow 0030. Targeted analytical/lifecycle/API tests: `10 passed`; full regression: `154 passed`. `alembic current` and `heads` both report the single `0032_calibration_adjudication` head; `git diff --check` passes. There are no proprietary scale rules, calibration does not establish clinical effectiveness or diagnosis, and no automatic promotion is applied to product consumers. Empty-database validation retains the prior environment limitation when no isolated PostgreSQL create-db permission/Docker daemon exists.
