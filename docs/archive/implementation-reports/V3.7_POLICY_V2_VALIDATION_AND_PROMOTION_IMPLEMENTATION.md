# V3.7 Policy V2 validation and promotion

V3.7 introduces `policy-validation-v1`: immutable datasets reference existing shadow decisions, freeze before runs, and produce an append-only validation report plus versioned registry status. Validation status is separate from runtime mode; `policy_decisions.mode` remains database-constrained to `shadow`.

Evidence is derived from preserved therapist feedback and actual-training observations. Unreviewed decisions are not counted as agreement or disagreement. Alignment is reported by category and is not policy accuracy. Safety audit checks shadow mode and forbidden payload concepts. Promotion is intentionally conservative: insufficient evidence is the default; an eligibility result never changes training.

The professional endpoints are under `/api/therapist/policy-v2/validation/...`; no patient/family route exists. CLI: `python -m app.modules.policy_validation.run --dataset <id> --report`.

The validation registry exposes policy/rules validation status separately from runtime permission. No registry state can create an active decision, alter `mode`, or modify a training session.

Known limitations: no active runtime mode, no automatic training changes, no clinical claim, no automatic reassessment. Split/subgroup/replay support is deliberately conservative and historical rules unavailable for replay are reported rather than substituted.
