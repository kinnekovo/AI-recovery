## 结论

## 实际数据结构

迁移 `0027_evaluation_runs_v3` 新增：

- `evaluation_runs`：患者、三评估域、三类来源、算法/配置/输入/质量快照、结果状态、画像准入、限制、采用状态和替代关系。
- `evaluation_dimension_results`：维度值（可空）、level、unit、`measured/not_observed/unavailable/not_applicable`、`measurement_quality`、证据与限制快照。
- `evaluation_review_revisions`：追加式 `confirmed/corrected/unjudgeable` 修订，保留自动值、修订值、覆盖证据、原因、复核人与未来重算 run 引用。

PostgreSQL 使用 JSONB；`patient_profile_id`、run/dimension/revision 的外键删除行为均明确为 `RESTRICT` 或审计保留所需的 `SET NULL`。`source_type/source_id` 是受三种来源约束的多态引用，无法安全指向一个单一外键；服务创建时验证来源归属，并将来源、Provider、契约和设备信息固化到 `input_provenance`，因此后续来源变动不会静默改变审计事实。

## 采用状态机与不可变性

```text
candidate --adopt--> adopted --replaced--> superseded
```

- 同一 `(source_type, source_id, domain)` 有 PostgreSQL 部分唯一索引，数据库层最多一个 `adopted`。
- 采用操作在事务中执行；PostgreSQL 使用事务 advisory lock，服务将旧 adopted 改为 `superseded`，新 run 写入 `supersedes_run_id` 后采用。
- 数据库触发器拒绝 run 的结果载荷改写和删除；只允许 `candidate→adopted` 与 `adopted→superseded`。维度和 revision 记录完全追加式，拒绝更新/删除。
- 对同一已 adopted run 的重复采用是幂等返回；部分唯一索引是并发及服务外写入的最终保护。

## R0 兼容

`QualityGateSnapshot` 直接承载 R0 `evidence_gate` 的 `eligible/reasons/loudness_unit/algorithm_version` 等结果；新 run 的 `config_snapshot` 固化 `r0-engineering-safety-v1` 和 R0 配置副本。本轮没有重新计算 `rehab-process-v2`，没有双写 Attempt，也没有放宽 dBFS、单位未知、mock、fallback 或低质量的 R0 决策边界。

## 权限边界

仅新增 `GET /api/evaluation-runs/{id}`，限定治疗师/管理员。服务会通过既有有效治疗师—患者分配校验访问 run 所属患者；患者、家属及未分配治疗师不能读取专业证据、Provider 快照或复核审计内容。
