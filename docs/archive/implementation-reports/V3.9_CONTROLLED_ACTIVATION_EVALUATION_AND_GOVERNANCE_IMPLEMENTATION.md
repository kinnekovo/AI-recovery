# V3.9 Controlled Activation Evaluation & Governance

## Architecture
V3.9 adds read-only engineering governance over V3.8 lifecycle records. `PolicyDecision` remains shadow; proposals still require therapist approval; governance never applies training.

## Evaluation dataset and lifecycle
Frozen datasets reference proposals and their decision, patient, session, version, profile, and V3.7 validation status. Lifecycle facts are read from approvals, executions, observations, rollbacks, and safety events; comments are excluded from aggregate reports.

## Governance
`controlled-governance-v1`, `controlled-evaluation-policy-v1`, and `controlled-governance-policy-v1` version the report and conservative internal engineering thresholds. Per policy/rules/action registry entries keep append-only transitions. Statuses include `insufficient_evidence`, `manual_only`, `eligible_for_streamlined_evaluation`, and `suspended`; none grants runtime permission.

## Safety and suspension
V3.8 now reads the governance registry only as an additional restriction. A suspended action type blocks proposal, approval recheck, and apply before training writes. `eligible_for_streamlined_evaluation` still requires the same explicit therapist approval.

## Metrics and limitations
Reports separate focus and difficulty actions and provide proposal/review, execution, conflict, rollback, blocked safety, completion-observation, and direction metrics. They describe operational behavior only: no clinical effectiveness, safety certification, causal inference, or autonomous-treatment claim is made.

## Version drift, APIs, and CLI
The run persists policy, rules, activation-policy, and adapter versions, so evidence is scoped to that exact version set; future version changes require a new frozen dataset/run rather than inheriting governance status. Professional endpoints create/freeze datasets, add/remove items, run governance evaluation, and read registry state. `python -m app.modules.controlled_governance.run --dataset <id> --report` and `python -m app.modules.controlled_governance.audit --dataset <id>` are offline/read-only with respect to training: neither has an approval, apply, or rollback option.
