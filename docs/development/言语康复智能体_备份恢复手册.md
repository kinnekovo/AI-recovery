# 言语康复智能体备份恢复手册

本文档面向小规模真实试用阶段，目标是在服务器故障、误删、迁移服务器或升级失败时，可以恢复患者账号、训练记录、评估报告和上传/生成的音频头像文件。

## 1. 必须备份的数据

系统数据分成两部分，缺一不可：

- PostgreSQL：用户、患者档案、训练会话、评估、报告、授权、绑定关系、文件元数据。
- `STORAGE_ROOT`：头像、声音样本、训练录音、生成口播音频。

数据库里只保存文件路径和元数据，不保存大文件。因此只备份数据库无法恢复录音；只备份 storage 也无法知道文件属于哪个患者。

## 2. 推荐备份频率

试用期建议：

- 数据库：每天至少一次。
- storage：每天至少一次，训练密集时每 6-12 小时一次。
- 每次发布前：手动备份数据库和 storage。
- 每次迁移服务器前：完整备份并在目标机器试恢复。

备份文件建议保留：

- 最近 7 天每日备份。
- 最近 4 周每周备份。
- 重要试用节点的手动备份长期保留。

## 3. 数据库备份

生产环境建议在后端 `.env` 中保存 `DATABASE_URL`，执行：

```bash
cd /opt/speech-rehab-agent/backend
set -a
source .env
set +a
mkdir -p /var/backups/speech-rehab
pg_dump "$DATABASE_URL" > /var/backups/speech-rehab/speech_rehab_db_$(date +%F_%H%M%S).sql
```

校验备份文件：

```bash
ls -lh /var/backups/speech-rehab/speech_rehab_db_*.sql
head -n 5 /var/backups/speech-rehab/speech_rehab_db_YYYY-MM-DD_HHMMSS.sql
```

如果数据库较大，可压缩：

```bash
gzip /var/backups/speech-rehab/speech_rehab_db_YYYY-MM-DD_HHMMSS.sql
```

## 4. Storage 备份

项目提供脚本：

```bash
cd /opt/speech-rehab-agent/backend
source .venv/bin/activate
python scripts/backup_storage.py --source /var/lib/speech-rehab/storage --output /var/backups/speech-rehab
```

脚本会生成：

- `speech_rehab_storage_时间戳.tar.gz`
- `speech_rehab_storage_时间戳.manifest.json`

manifest 会记录备份来源、归档路径、文件数量和总字节数。

本地开发环境也可以验证：

```powershell
cd backend
python scripts\backup_storage.py --source ..\storage --output ..\backups
```

## 5. 恢复顺序

恢复时先停服务：

```bash
sudo systemctl stop speech-rehab-api
```

恢复数据库：

```bash
dropdb speech_rehab_agent
createdb speech_rehab_agent
psql "$DATABASE_URL" < /var/backups/speech-rehab/speech_rehab_db_YYYY-MM-DD_HHMMSS.sql
```

恢复 storage：

```bash
mkdir -p /var/lib/speech-rehab
tar -xzf /var/backups/speech-rehab/speech_rehab_storage_YYYYMMDDTHHMMSSZ.tar.gz -C /var/lib/speech-rehab
```

确认 `.env`：

```env
STORAGE_ROOT=/var/lib/speech-rehab/storage
```

修正权限：

```bash
sudo chown -R www-data:www-data /var/lib/speech-rehab/storage
```

执行迁移到当前代码版本：

```bash
cd /opt/speech-rehab-agent/backend
source .venv/bin/activate
alembic upgrade head
python scripts/check_database.py
```

启动服务：

```bash
sudo systemctl start speech-rehab-api
curl https://your-domain.example/api/health
```

## 6. 迁移服务器

迁移到新服务器时：

1. 在旧服务器执行数据库和 storage 完整备份。
2. 在新服务器部署同版本代码。
3. 安装后端和前端依赖。
4. 恢复数据库。
5. 恢复 storage。
6. 修改新服务器 `.env` 中的 `DATABASE_URL` 和 `STORAGE_ROOT`。
7. 执行 `alembic upgrade head`。
8. 运行 `/api/health`。
9. 用试用账号验证头像、训练录音、报告和家属/治疗师权限。

## 7. 恢复验收

恢复后至少检查：

- 患者可以登录。
- 患者智能体头像可以显示。
- 历史训练录音可以播放。
- 治疗师只能看到被分配患者。
- 家属只能看到 active 绑定患者。
- 阶段报告可以打开和打印。
- `/api/health` 数据库、storage、provider 状态可读。

## 8. 注意事项

- 不要把备份文件放在公开 Web 目录。
- 备份文件可能包含患者隐私数据，传输和保存都应加密。
- 声音样本和训练录音属于敏感数据，恢复后仍必须通过 `/api/files/{id}/content` 鉴权访问。
- 迁移前后如果改变 `STORAGE_ROOT`，必须确认数据库中文件路径是否仍指向有效位置。
