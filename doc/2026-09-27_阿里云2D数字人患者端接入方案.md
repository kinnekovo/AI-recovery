# 阿里云 2D 数字人患者端接入方案

日期：2026-09-27  
状态：技术方案 / 待商务与产品生命周期确认

## 1. 结论

患者端应采用“现有康复训练链路 + 阿里云 2D 数字人表现层”的架构，而不是让阿里云接管对话和训练逻辑。

推荐组合：

- 渲染：**2D 云渲染**。当前患者端是 Vue Web，阿里云 2D 端渲染只支持 iOS/Android 原生 SDK，不适用于现有 Web 产品。
- 集成：**音频驱动**。系统继续使用既有 ASR、康复场景对话、评估和 TTS；阿里云只消费系统生成的语音并输出口型、表情和视频流。
- 形象：一期用官方形象完成技术验证；个性化形象只在阿里云书面确认生命周期、采购和存量资产安排后开放。
- 降级：阿里云不可用、并发占满或授权撤回时，自动切换现有本地 2.5D 头像 + TTS，不阻断训练。

不建议将“2D 云渲染全链路”作为正式方案。它会重复引入阿里 ASR、LLM、TTS，绕开现有康复对话策略、训练状态机、临床安全边界和评估证据链。

## 2. 必须先处理的产品生命周期风险

阿里云 2026 年 9 月发布的公告说明：

- 数字人形象定制、平台积分和会员订阅、数字人直播商品自 **2026-10-11** 起停止新购；
- 自 **2027-04-11** 起停止存量客户续订及版本更新；
- 已定制数字人形象会随绑定应用停止服务，相关平台服务计划于 **2027-10-11** 全面停止。

公告没有在同一段中明确说明 2D 实时对话商品是否同步停止新购，但“患者个性化形象”依赖形象定制，且已定制形象会随绑定应用停止。因此在收到阿里云书面答复前，本项目只能把该能力视为**过渡性增强能力**，不能作为长期唯一方案。

立项/采购前应通过工单书面确认：

1. 2D 云渲染音频驱动实时对话能否在 2026-10-11 后新购、扩容和续费；
2. 图片免训、图片训练、小样本视频和高精度视频四类资产分别何时停止创建、调用和下载；
3. 已购买实例和已定制资产的最终可用日期及退款/迁移政策；
4. Web SDK、OpenAPI 和 RTC 服务的维护终止时间；
5. 用户照片、生成资产和日志的存储地域、保留周期、删除接口和删除证明；
6. 医疗健康场景是否需要额外审核、合同条款或数据处理协议。

若答复无法覆盖预计试用周期，应停止生产接入，只保留短期演示 PoC，并同步评估可迁移供应商或自有端侧方案。

## 3. 官方产品能力与选型

阿里云 2D 实时对话由两组选择组成。

| 维度 | 选项 | 官方能力 | 对本项目的判断 |
| --- | --- | --- | --- |
| 渲染 | 云渲染 | 云端生成视频流；支持 Web、iOS、Android | **选择**，适配当前 Vue Web |
| 渲染 | 端渲染 | 终端本地推理和渲染；2D 仅 iOS/Android 原生 | 当前不选；未来原生 App 可复评 |
| 集成 | 全链路 | 集成 ASR、LLM、TTS、数字人驱动 | 不选，会绕开康复业务链路 |
| 集成 | 音频驱动 | 客户上传音频，阿里云只驱动数字人 | **选择**，保留现有智能内核 |

官方目录价（实际以购买页为准）：

| 商品 | 价格 | 说明 |
| --- | ---: | --- |
| 2D 云渲染全链路 | 3000 元/路/月 | 独占并发路数；另计 LLM 费用 |
| 2D 云渲染音频驱动 | 2400 元/路/月 | 独占并发路数，只提供音频驱动 |
| 2D 端渲染全链路 | 0.06 元/分钟 | 按秒计费；不支持 2D Web SDK |
| 2D 端渲染音频驱动 | 250 元/月/设备或 25000 元/月/应用 | iOS/Android 原生授权 |

“路”是同时在线的会话数，不是注册用户数。1 路实例只允许 1 个患者同时使用云数字人，因此一期应配置并发闸门和本地降级，而不是让排队阻断训练。

## 4. 目标架构

```text
患者 Web 端
  ├─ 录音、字幕、训练控制
  ├─ Avatar Runtime（统一状态机）
  │    ├─ AliyunAudioDrivenProvider（增强）
  │    └─ Local2_5DProvider（默认/降级）
  └─ 阿里云 Web SDK（只接收短期 RTC 会话参数）
             │
             ▼
本项目后端
  ├─ 患者/陪伴者授权与资产映射
  ├─ Avatar Session Broker（鉴权、租约、并发、超时）
  ├─ 训练状态机和场景对话策略
  ├─ ASR / 语义提取 / 康复评估
  ├─ TTS 与受保护音频
  └─ 阿里云 OpenAPI（服务端凭据）
             │
             ▼
阿里云
  ├─ 个性化 2D 资产（条件启用）
  ├─ 音频驱动云渲染
  └─ RTC 视频流
```

关键边界：

- 患者语音先进入现有训练接口，而不是直接交给阿里云全链路。
- 现有系统产出下一轮康复话术和 TTS 音频后，再把音频送入数字人驱动 SDK。
- 阿里云输出只影响展示，不影响训练完成、评分、推荐或临床记录。
- AccessKey/Secret、实例 ID 管理能力和资产创建 API 只存在于后端；浏览器仅获得短时会话参数。

## 5. 用户流程

### 5.1 个性化数字人创建

1. 用户选择官方形象，或上传已获授权的单人正面照片。
2. 页面分别展示本地保存、提交阿里云、用途、保存期限、撤回方式，不默认勾选同意。
3. 浏览器本地做人脸数量、清晰度和构图检查；后端再做格式、大小和恶意文件校验。
4. 后端创建阿里资产任务并保存供应商资产 ID、类型、状态和源文件版本。
5. 对异步训练类型轮询任务状态；成功后创建/绑定“云渲染音频驱动”项目。
6. 用户预览形象；审核不通过时显示可操作原因，不自动重复扣费提交。
7. 用户可随时改回本地 2.5D 或官方形象，并发起删除供应商资产。

一期建议只开放“官方形象 + 1 个内部测试图片形象”。不要在生命周期和费用未确认前向所有患者开放自助创建。

### 5.2 训练中的实时交互

```text
进入任务
→ 后端申请数字人会话租约
→ Web SDK 建立 RTC 流
→ 系统生成任务说明/TTS
→ 音频驱动数字人播报
→ 播报结束后才允许开麦
→ 患者录音
→ 现有 ASR/对话策略/评估处理
→ 生成追问或反馈/TTS
→ 再次驱动数字人播报
```

交互优先级：

```text
患者开始录音 > 停止播报 > 新一轮回复 > 旧回复 > 待机动画
```

数字人播报和患者录音不得重叠。用户点击录音时必须立即中止云端播报并确认音频输出已停止，再开启麦克风。

## 6. 对现有代码的审计结论

项目并非从零开始，已经具备较完整的骨架：

- 前端已安装 `lm-avatar-chat-sdk@1.1.0`；
- 已有 `AvatarProvider` / `useAvatarRuntime` 抽象和本地 2.5D 降级；
- 已有 `AliyunCloudAvatarProvider`、RTC 容器和会话创建/关闭接口；
- 后端已有 LingMou SDK、图片免训形象创建、对话配置创建和会话 Broker；
- 数据库已有阿里资产状态、配置 ID、会话租约及相关迁移；
- 已有图片授权校验、服务端凭据隔离和单路并发保护；
- 训练页已把任务示范、场景追问和反馈文本接入 Avatar Runtime。

当前实现与推荐正式方案仍有差距：

1. 前端当前使用全链路 cloud SDK 的 `requestToRespond(transcript, text)`；虽然禁用了音频输入，但仍由阿里侧把文本转成语音。正式版应改为音频驱动 SDK，并使用现有 TTS 音频。
2. `speak(input)` 收到了 `audioUrl`，阿里 Provider 却忽略该字段，导致本地声音配置与云数字人声音不一致。
3. 图片免训自动创建直接绑定患者自助流程，受到 2026-10-11 停止新购公告的重大影响，需要功能开关和运营白名单。
4. 当前并发保护按单个实例全局互斥；需要支持实例池、原子占用、租约过期回收和多进程一致性。
5. 会话建立失败会静默降级，用户可继续训练是正确的，但缺少可观测错误码、失败率、首帧延迟、占用时长和费用指标。
6. 供应商异常场景、SDK 状态映射、租约回收、重复资产创建和前端降级的自动化测试不足。
7. 目前没有完整的供应商资产删除/授权撤回闭环和删除审计记录。

因此无需重写训练系统，主要工作是把现有“云全链路文本驱动”改造成“云音频驱动表现层”，并补齐生产治理。

## 7. 接口与数据建议

### 7.1 后端接口

```text
POST   /api/avatar/assets                 创建供应商资产任务
GET    /api/avatar/assets/{id}            查询训练/审核状态
DELETE /api/avatar/assets/{id}            撤回并删除供应商资产
POST   /api/avatar/sessions               申请会话租约和 RTC 参数
POST   /api/avatar/sessions/{id}/heartbeat 续租
DELETE /api/avatar/sessions/{id}           主动关闭
POST   /api/training/avatar-speech         生成/获取本系统 TTS 音频
```

所有创建接口使用幂等键；资产创建结果不确定时进入 `manual_review`，禁止自动重提，避免重复扣费或生成重复资产。

### 7.2 资产字段

建议把阿里字段从 `agents` 主表逐步拆到供应商资产表：

```text
avatar_assets
  id, agent_id, provider, asset_type
  provider_asset_id, provider_project_id
  source_file_id, source_sha256
  status, failure_code, manual_review_required
  consent_record_id, consent_version
  created_at, ready_at, deletion_requested_at, deleted_at
```

会话表增加：

```text
provider_instance_id, lease_expires_at, heartbeat_at
close_reason, first_frame_ms, session_duration_seconds
fallback_reason, provider_error_code
```

不得记录 RTC token、AccessKey、患者原始语音或供应商原始异常全文。

## 8. 可用性、并发和降级

### 8.1 状态机

```text
idle → connecting → ready → speaking → listening → thinking → speaking
                    └──────────────────────────────→ local_fallback
```

前端只通过统一状态机更新画面，不能让供应商 SDK 回调直接改变训练业务状态。

### 8.2 降级顺序

```text
阿里云个性化形象 + 云渲染
→ 阿里云官方形象 + 云渲染（资产问题时）
→ 本地 2.5D 个性化头像 + 后端 TTS
→ 本地静态头像 + 浏览器 TTS
→ 文字字幕
```

并发占满、RTC 首帧超时、SDK 初始化失败和阿里接口异常都应在 3–5 秒内进入本地降级。降级不弹阻塞式错误，只提示“已切换到基础陪伴模式”。

### 8.3 容量建议

PoC 先购买/申请 1 路，用本地模式承接并发溢出。通过实际监控得到峰值同时训练人数、平均会话时长和云模式使用率后再决定路数。不要按注册患者数线性采购。

## 9. 安全、隐私和临床边界

- 人像、声音和健康训练数据分别授权；声音克隆不是本次 2D 接入的前置条件。
- 明示阿里云为第三方处理方，说明数据类别、目的、期限和撤回影响。
- 儿童或无完全民事行为能力患者需要监护人流程和被拍摄者形象授权。
- 供应商只接收生成数字人必需的照片/音频，不发送诊断、评分、病历和完整对话历史。
- 数字人不得宣称医生身份，不给出诊断、用药或替代治疗建议。
- 数字人画面是陪伴反馈，不作为标准构音口型示范；精确构音教学继续使用经审核的视频/图示。
- 所有播报显示同步字幕，提供停止、重播和减少动态效果；网络失败时训练仍可完成。
- 凭据使用 RAM 最小权限和工作负载身份，禁止把长期 AccessKey 返回浏览器。

## 10. 监控与验收指标

技术指标：

- 会话申请成功率 ≥ 99%；
- RTC 首帧 P95 ≤ 3 秒；
- 数字人回复首帧 P95 ≤ 1.5 秒（从音频可用开始计算）；
- 音画不同步 P95 ≤ 200 ms；
- 中断生效 P95 ≤ 300 ms；
- 租约异常占用率 < 0.5%；
- 云服务失败时本地降级成功率 ≥ 99.9%；
- 训练完成率不得低于关闭数字人时的基线。

产品/康复指标：

- 患者能判断“谁在说、何时轮到自己”；
- 数字人不会诱导患者照着不准确口型模仿；
- 数字人开启后任务完成率、平均训练轮次和退出率无显著恶化；
- 治疗师确认数字人话术与场景对话记录一致；
- 授权撤回后无法再创建新会话，供应商资产删除可审计。

## 11. 分阶段实施

### Gate 0：商务与生命周期确认（立即执行）

- 向阿里云提交工单，取得第 2 节六项问题的书面答复；
- 确认是否能在 2026-10-11 前合法采购所需形象和实时对话商品；
- 若无法保障试用周期，终止生产依赖，转为短期 PoC。

### Phase 1：1 路官方形象 PoC（2–3 天）

- 使用官方形象，不上传真实患者/家属照片；
- 贯通 Web SDK、RTC 首帧、播报、中断、关闭和本地降级；
- 用固定测试音频验证音频驱动，不接训练评分。

### Phase 2：接入现有训练链路（3–5 天）

- 将 Provider 从全文本驱动改为音频驱动；
- 复用 `/training/avatar-speech` 输出的受保护 TTS 音频；
- 接入跟读示范、场景追问、鼓励反馈；
- 保证开始录音前完成云播报中断。

### Phase 3：个性化形象受控试用（3–5 天）

- 仅对白名单测试账号开放；
- 完成分项授权、异步状态、人工复核和删除流程；
- 增加实例池租约、心跳回收、指标和告警。

### Phase 4：小规模患者试用

- 灰度开关按患者/机构控制；
- 对照本地 2.5D 基线观察完成率、注意负担和主观接受度；
- 只有在供应商生命周期、合规和体验均达标后扩大范围。

## 12. Go / No-Go 条件

Go：

- 阿里云书面确认服务覆盖项目预期试用周期；
- Web 音频驱动 SDK、实例和目标形象类型可以购买并可续；
- 授权、删除、降级和并发保护通过验收；
- 断开阿里云后患者仍能完成全部训练。

No-Go：

- 无法确认 2027 年后的资产/应用可用性；
- 必须将患者健康数据或完整对话交给供应商才能运行；
- 个性化资产无法删除或无法提供处理边界；
- SDK/API 与当前购买商品不匹配；
- 数字人失败会阻塞录音、评估或训练完成。
