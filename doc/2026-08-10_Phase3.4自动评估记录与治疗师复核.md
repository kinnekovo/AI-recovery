# 2026-08-10 Phase 3.4 自动评估记录与治疗师复核

## 本次纠偏

Phase 3.4 最初实现为“治疗师端阶段性评估录入”，主流程偏向治疗师手动填写 WAB、CADL、接受度等专业量表。经过产品边界复盘后，该方向调整为：

```text
患者训练/测试 -> 系统自动分析 -> 自动生成评估记录 -> 治疗师复核/确认/修正 -> 患者端展示简化结果
```

新的角色边界如下：

- 患者端负责训练、录音、触发分析、查看低认知负担的康复记录。
- 系统负责根据训练分析结果自动生成阶段评估记录。
- 治疗师端负责查看自动评估、确认、修正指标和留下临床备注。
- 手动补录只作为辅助能力，不再作为 Phase 3.4 主流程。

## 后端改动

### 1. 评估记录生命周期

`assessment_sessions` 在原有阶段性评估表基础上新增复核相关字段：

```text
source_attempt_id
review_status
reviewed_by_user_id
reviewed_at
therapist_notes
```

`review_status` 当前支持：

```text
auto_generated
pending_review
confirmed
adjusted
```

其中当前 MVP 主流程使用：

- `pending_review`：系统自动生成后等待治疗师复核。
- `confirmed`：治疗师确认自动评估可用。
- `adjusted`：治疗师对自动评估指标或说明做过修正。

### 2. 自动生成评估记录

训练分析完成后，系统会基于过程性监控指标自动生成一条 `assessment_sessions` 记录：

```text
script_accuracy
error_count
speech_rate
loudness
```

触发位置：

```text
backend/app/modules/scoring/service.py
```

核心逻辑：

- 患者完成录音并触发 `/api/attempts/{attempt_id}/analyze`。
- 分析链路写入 `attempt_evaluations`。
- 同步生成 `assessment_sessions`。
- 生成记录的 `evaluation_source = mock_ai`。
- 生成记录的 `review_status = pending_review`。
- 生成记录通过 `source_attempt_id` 关联本次训练作答。

### 3. 历史数据回填

由于 Phase 3.4 重构前已经存在训练记录和过程指标，但当时还没有自动评估记录，因此新增了治疗师端读取时的回填逻辑：

```text
backfill_auto_assessments
backfill_profile_auto_assessments
```

位置：

```text
backend/app/modules/therapist/service.py
```

回填规则：

- 找到已完成分析的 `attempts`。
- 检查是否已有对应 `assessment_sessions.source_attempt_id`。
- 若没有，并且存在完整过程指标，则补生成 `pending_review` 自动评估记录。

本地当前测试数据已回填：

```text
assessment_sessions_before 0
assessment_sessions_after 3
```

### 4. 治疗师端接口

新增/更新接口：

```text
GET   /api/therapist/patients
GET   /api/therapist/patients/{patient_user_id}/assessments
GET   /api/therapist/patients/{patient_user_id}/assessments/compare
PATCH /api/therapist/patients/{patient_user_id}/assessments/{assessment_id}/review
POST  /api/therapist/patients/{patient_user_id}/assessments
```

说明：

- `GET /patients` 返回患者队列，并包含 `pending_review_count` 和 `latest_assessment_at`。
- `GET /assessments` 返回指定患者的自动评估与复核历史。
- `PATCH /review` 用于治疗师确认或修正自动评估。
- `POST /assessments` 暂时保留为补录入口，但不作为主流程。


当前数据库版本：

```text

```

## 前端改动

### 1. 治疗师端页面重构

更新文件：

```text
frontend/src/views/therapist/TherapistAssessmentsView.vue
frontend/src/api/therapist.ts
frontend/src/types/api.ts
frontend/src/assets/styles.css
```

页面由“量表录入与对比”重构为“自动评估复核”工作台。

### 2. 当前界面结构

治疗师端 `/therapist/assessments` 当前包含：

- 顶部待复核总数与当前患者记录数。
- 左侧患者队列，优先显示有待复核记录的患者。
- 中间自动评估记录列表，展示状态、时间和核心指标摘要。
- 右侧复核详情，展示系统初步判断、指标摘要、系统说明和治疗师备注。
- 指标修正入口默认收起，避免页面看起来像手动填表。
- 底部趋势对比，用于比较最早和最近一次评估变化。

### 3. 前端交互原则

本阶段治疗师端强调“复核”，不是“录入”：

- 自动评估指标优先以摘要卡片展示。
- 治疗师可以一键确认自动评估。
- 只有需要调整时，才展开“需要修正指标”。
- 治疗师备注用于说明临床观察和修正依据。
- 患者端不暴露 WAB、CADL、dBA、字/min 等专业细节。

## 患者端影响

患者端不新增专业表单。

患者端仍然只展示简化康复记录：

- 表达完整度
- 需要留意的地方
- 说话节奏
- 声音状态
- 下一步训练建议

自动评估记录归属于患者，但专业复核入口只在治疗师端。

## 人工测试路径

### 1. 患者端生成自动评估

使用患者账号登录：

```text
/training
```

完成一次训练：

1. 创建训练会话。
2. 录音或上传录音。
3. 点击分析。
4. 系统返回训练反馈。
5. 后端自动生成 `pending_review` 评估记录。

### 2. 治疗师端复核

使用治疗师账号登录：

```text
therapist_demo / 123456
```

打开：

```text
/therapist/assessments
```

预期：

- 患者队列显示待复核数量。
- 自动评估列表显示待复核记录。
- 详情区显示系统初步判断和过程指标。
- 点击“确认自动评估”后状态变为已确认。
- 展开“需要修正指标”并保存后状态变为已修正。

## 后续 Phase 3.5 提醒

Phase 3.5 能力画像 MVP 应以本阶段数据为输入：

- 已复核的自动评估记录。
- 治疗师修正后的指标。
- 近期过程性监控趋势。
- 治疗师复核备注。

建议 Phase 3.5 避免重新引入患者端专业量表展示，而是把复核后的评估数据沉淀为患者能力画像和训练推荐依据。
