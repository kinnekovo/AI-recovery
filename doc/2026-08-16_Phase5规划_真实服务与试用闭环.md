# Phase 5 规划：真实服务与试用闭环

日期：2026-08-16

## 一、Phase 5 总目标

Phase 4 已完成三端边界、推荐策略、趋势归因、自适应推荐、语音评估 provider 预留和旧接口软退役。Phase 5 不再重新设计三端主职责，而是把当前 MVP 从“可演示系统”推进到“可真实试用系统”。

Phase 5 的核心目标是：

```text
真实语音数据进入系统
-> 稳定生成可追踪评分
-> 推荐闭环继续运行
-> 治疗师和家属能看懂进展
-> 系统能导出报告和保留试用证据
```

## 二、当前基线

### 已具备能力

- 患者端完成训练任务组。
- 自动生成训练反馈。
- 能力画像刷新。
- 推荐策略配置化。
- 趋势归因与三端提醒。
- 自适应推荐增强。
- 家属-患者正式绑定。
- 治疗师端三模块工作台。
- 语音评估 provider 环境变量预留。
- 旧推荐复核接口标记 deprecated。

### 仍是 MVP 或 mock 的部分

- ASR 转写仍为 mock。
- 声学分析仍为 mock。
- LLM 反馈仍为 mock。
- 报告还偏页面展示，缺少正式导出。
- 缺少真实试用数据质量控制。
- 缺少服务异常、低质量录音和重试机制。

## 三、Phase 5 产品边界

### 患者端继续负责

- 完成每日推荐任务组。
- 自主安排额外训练。
- 查看简单反馈和康复记录。
- 理解“今天为什么这样练”。

患者端不增加专业量表、不展示复杂归因。

### 家属端继续负责

- 查看绑定患者水平和趋势。
- 理解陪伴提醒。
- 观察训练坚持情况。

家属端不参与评分、复核和推荐调参。

### 治疗师端继续负责

- 查看每次训练记录和评分结果。
- 查看趋势、归因和提醒。
- 必要时用自然语言补充训练方向。
- 导出或查看阶段性报告。

治疗师端不恢复“每条推荐审批后台”。

## 四、Phase 5 分批规划

## Phase 5.1 真实 ASR Provider 接入

### 目标

将当前 mock ASR 替换为真实语音转写 provider，同时保持接口字段不变。

### 建议实现

- 新增真实 ASR provider 类。
- 在 `ASR_PROVIDER` 中支持真实 provider 名称。
- 支持读取：

```env
ASR_PROVIDER=real_provider_name
ASR_API_KEY=
ASR_BASE_URL=
```

- 将真实转写结果写入 `AttemptAnalysisResult.asr_text`。
- 保留 mock fallback。
- 记录实际 provider 与 requested provider。

### 验收标准

- 上传真实录音后能得到真实中文转写。
- ASR 服务异常时 fallback 不导致训练流程崩溃。
- 患者端反馈结构不变。
- 治疗师端训练记录能看到真实转写关联的评分结果。

## Phase 5.2 真实声学分析与音频质量检测

### 目标

把录音质量、语速、音量、长停顿等指标从 mock 过渡到真实分析。

### 建议实现

- 新增真实 acoustic provider。
- 映射到现有过程指标：

```text
speech_rate
loudness
error_count
```

- 增加音频质量字段，例如：

```text
quality_status
quality_reason
noise_level
too_short
too_quiet
```

- 对低质量录音给患者明确提示：

```text
录音声音太轻，请靠近一点再试一次。
录音时间太短，请完整说完句子后再提交。
```

### 验收标准

- 真实录音能生成语速、音量、停顿指标。
- 低质量录音不会被误当作能力下降。
- 患者端能看到可执行的重录提示。
- 推荐趋势能区分“能力问题”和“录音质量问题”。

## Phase 5.3 真实 LLM 反馈与安全边界

### 目标

用真实 LLM 生成更自然的中文反馈，但保持评分维度和医疗安全边界。

### 建议实现

- 新增真实 LLM feedback provider。
- 输入只包含：

```text
目标文本
ASR 转写
过程指标
任务类型
患者端可见上下文
```

- 输出仍映射到：

```text
overall_score
content_score
clarity_score
fluency_score
loudness_score
prompt_dependence_score
main_strength
main_issue
suggestion
```

- 增加安全约束：

```text
不做诊断
不承诺疗效
不替代治疗师意见
不用吓人的医学表述
```

### 验收标准

- 患者端反馈自然、简短、可执行。
- 输出字段稳定，不影响推荐算法和三端页面。
- LLM 输出异常时 fallback 到规则反馈。

## Phase 5.4 训练报告导出 MVP

### 目标

把当前页面型康复记录升级为可导出的阶段报告，方便治疗师、项目汇报或试用留档。

### 建议实现

- 新增报告导出接口：

```text
GET /api/reports/export?format=pdf
```

- 报告内容包括：

```text
患者基本信息
训练次数
最近训练表现
过程指标趋势
推荐变化说明
治疗师自然语言备注
阶段性评估摘要
```

- PDF 先做 MVP 模板，不做复杂排版。
- 患者端可查看简化报告，治疗师端可导出正式报告。

### 验收标准

- 治疗师端能导出某患者报告。
- 报告不展示不适合患者/家属理解的内部字段。
- 报告中的指标与系统页面一致。

## Phase 5.5 试用数据闭环与质控看板

### 目标

为小规模真实试用准备数据质量和系统运行观察能力。

### 建议实现

- 新增试用质控摘要：

```text
训练完成率
录音失败率
低质量录音比例
ASR 失败次数
评分失败次数
推荐任务完成率
家属查看次数
治疗师查看次数
```

- 可先做后端接口和治疗师/管理员只读面板。
- 不进入患者端。

### 验收标准

- 能判断试用过程中问题来自系统、录音质量还是患者未完成训练。
- 能快速发现 provider 异常。
- 能导出或截图用于阶段汇报。

## Phase 5.6 错误处理、重试与可观测性

### 目标

让真实服务失败时系统可恢复、可追踪、可解释。

### 建议实现

- provider 调用超时控制。
- 外部服务异常分类：

```text
asr_failed
acoustic_failed
llm_failed
audio_quality_failed
provider_timeout
```

- `Attempt.analysis_status` 扩展失败原因。
- 前端展示可理解错误。
- 后端记录 provider raw payload 和错误摘要。

### 验收标准

- 外部服务失败不会导致用户卡死。
- 患者能知道是否需要重录或稍后再试。
- 开发者能通过日志和数据库定位 provider 问题。

## 五、推荐实施顺序

### 第一批：真实语音链路

```text
Phase 5.1 真实 ASR Provider 接入
Phase 5.2 真实声学分析与音频质量检测
Phase 5.3 真实 LLM 反馈与安全边界
```

原因：Phase 5 最大风险是真实语音数据质量。先把数据来源变真，推荐和趋势才有真实意义。

### 第二批：交付与试用

```text
Phase 5.4 训练报告导出 MVP
Phase 5.5 试用数据闭环与质控看板
```

原因：真实试用需要可汇报、可复盘、可留档。

### 第三批：稳定性工程

```text
Phase 5.6 错误处理、重试与可观测性
```

原因：真实 provider 接入后，网络失败、音频质量和服务波动会成为主要问题。

## 六、Phase 5 不建议做的事

暂不建议：

- 重做三端页面结构。
- 重新引入治疗师逐条审批推荐。
- 在患者端展示复杂专业指标。
- 过早做复杂后台配置系统。
- 在没有真实试用数据前训练个性化模型。

## 七、Phase 5 关键验收标准

Phase 5 完成后，系统应满足：

1. 真实录音可以产生真实转写和声学指标。
2. mock fallback 仍可用。
3. 评分字段保持稳定，三端页面不用重构。
4. 推荐策略能使用真实指标继续自适应。
5. 治疗师可以导出阶段报告。
6. 家属可以看到真实趋势和陪伴提醒。
7. 系统能区分训练表现问题、录音质量问题和 provider 失败。

## 八、需要提前确认的外部资源

进入 Phase 5.1 前，需要确认：

```text
ASR 服务 provider
ASR API key
ASR 支持的音频格式
ASR 是否返回时间戳或置信度
声学分析 provider
LLM feedback provider
模型名称和 base URL
真实服务调用预算
```

如果暂时没有完整真实服务，可以先只接 ASR，再逐步接声学分析和 LLM 反馈。

## 九、Phase 5 收口判断

Phase 5 的收口标准不是“功能更多”，而是：

```text
真实数据进入闭环，系统仍然稳定、可解释、可交付。
```

当真实语音链路、报告导出和试用质控都跑通后，系统可以进入 Phase 6：临床试用优化、数据标注与更正式的疗效评估。
