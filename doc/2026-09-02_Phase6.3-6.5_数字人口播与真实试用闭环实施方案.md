# Phase 6.3-6.5 数字人口播与真实试用闭环实施方案

日期：2026-09-02

## 一、当前状态确认

当前项目已经完成了患者端 MVP 主闭环、能力画像、推荐策略、三端观察入口、真实 ASR 和本地声学分析 Provider 预留/接入，以及 Phase 6.1-6.2 的数字人运行时和患者端陪练界面。

最新完成阶段为：

```text
Phase 6.1-6.2 数字人运行时与患者端陪练界面
```

已经具备的关键基础：

- 后端已有 `integrations/tts/provider.py`，当前默认 `MockTTSProvider` 会生成 wav 文件。
- 后端已有 `FileAsset` 和 `FileType.generated_audio`，欢迎语音已经使用该模式持久化。
- 后端已有 `/api/files/{file_id}/content` 文件访问方式。
- 患者当前智能体保存在 `PatientProfile.current_agent_id`。
- 训练会话已经保存 `TrainingSession.agent_id`。
- 前端 `useAvatarRuntime.speak(text, audioUrl?)` 已经预留 `audioUrl`。
- 前端 `Static2DAvatarProvider` 已经支持 `audioUrl` 播放，缺省时 fallback 到浏览器 `speechSynthesis`。

因此下一阶段不需要重写训练系统，而是把“数字人口播文本 -> 后端 TTS 合成 -> 文件持久化 -> 前端 Avatar 播放”接入到现有训练流程中。

## 二、本次一次迭代目标

本次迭代建议一次完成 Phase 6.3、Phase 6.4、Phase 6.5 的 MVP 版本。

目标链路：

```text
患者进入训练
-> 系统根据训练任务生成数字人口播文案
-> 后端使用当前智能体 voice_external_id 合成音频
-> 保存为 generated_audio 文件资产
-> 前端拿到 audio_url
-> Avatar Runtime 播放真实音频并保持 speaking 状态
-> 失败时回退到浏览器 TTS，不阻塞训练
```

本轮完成后，患者端体验应从“页面文字 + 浏览器朗读”升级为“当前陪伴智能体用可持久化音频进行训练引导”。

## 三、阶段拆分

## Phase 6.3：数字人口播 TTS 接口

### 目标

新增一个后端接口，用于给患者当前训练场景生成数字人口播音频。

接口只负责生成训练引导语音，不改变训练评分、推荐、ASR、声学分析等业务链路。

### 建议接口

```text
POST /api/training/avatar-speech
```

### 请求体

```json
{
  "scene": "session_intro",
  "session_id": "uuid 可选",
  "session_task_id": "uuid 可选",
  "text": "请跟我说这一句：今天天气很好。"
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| scene | string | 是 | 口播场景，例如 `training_intro`、`session_intro`、`task_demo`、`next_task`、`result_encouragement` |
| session_id | UUID | 否 | 当前训练会话，用于校验归属和后续追踪 |
| session_task_id | UUID | 否 | 当前训练任务，用于校验归属和文案生成 |
| text | string | 是 | 前端或后端生成的最终口播文本 |

### 响应体

```json
{
  "text": "请跟我说这一句：今天天气很好。",
  "audio_file_id": "uuid",
  "audio_url": "/api/files/{file_id}/content",
  "provider": "mock",
  "fallback": false
}
```

### 后端实现位置

建议新增/修改：

```text
backend/app/modules/training/schema.py
backend/app/modules/training/service.py
backend/app/modules/training/router.py
backend/app/integrations/tts/provider.py
```

### 后端实现细节

1. 在 `training/schema.py` 新增：

```python
class AvatarSpeechCreate(BaseModel):
    scene: str
    session_id: UUID | None = None
    session_task_id: UUID | None = None
    text: str


class AvatarSpeechRead(BaseModel):
    text: str
    audio_file_id: UUID | None = None
    audio_url: str | None = None
    provider: str
    fallback: bool = False
```

2. 在 `training/service.py` 新增 `create_avatar_speech()`。

核心逻辑：

- 获取当前患者 `PatientProfile`。
- 确认 `current_agent_id` 存在。
- 读取当前 `Agent`。
- 如果传入 `session_id`，校验训练会话属于当前患者。
- 如果传入 `session_task_id`，校验任务属于当前训练会话或当前患者。
- 限制 `text` 长度，建议 4-120 个中文字符左右，避免误传长文本。
- 优先使用 `agent.voice_external_id` 调用 TTS。
- 若缺少 `voice_external_id`，可以使用 `"default"` 作为 voice_id，并标记 `fallback=True`。
- 合成音频后创建 `FileAsset(file_type=FileType.generated_audio)`。
- 返回 `public_url(asset)`。

3. 复用欢迎语音持久化模式。

当前 `agents/service.py` 的 `generate_welcome_audio()` 已经证明可行：

```text
TTSProvider.synthesize()
-> 创建 FileAsset
-> 返回 public_url(asset)
```

训练口播应复用同一思路。

4. 在 `training/router.py` 新增：

```python
@router.post("/avatar-speech")
def create_avatar_speech(...):
    result = service.create_avatar_speech(db, current_user, payload)
    return api_success(result.model_dump(mode="json"))
```

5. 在 `tts/provider.py` 增强 provider 元信息。

建议让 Provider 暴露：

```python
class TTSProvider:
    name = "base"
    def synthesize(self, text: str, voice_id: str) -> str:
        raise NotImplementedError
```

`MockTTSProvider.name = "mock"`。

后续真实 TTS Provider 可以读取：

```env
TTS_PROVIDER=mock
TTS_API_KEY=
TTS_BASE_URL=
TTS_MODEL=
```

当前本轮可以先补配置字段，但真实外部 Provider 不作为硬依赖。

### 数据库是否需要迁移

MVP 版本不强制新增表。

原因：

- 音频文件已经能通过 `files` 表保存。
- 当前需求是“训练口播音频可播放、可追溯到用户”，不需要先建立完整口播日志。

可选增强：

```text
avatar_speech_events
```

字段包括：

- id
- patient_profile_id
- agent_id
- training_session_id
- session_task_id
- scene
- text
- audio_file_id
- provider
- fallback
- created_at

建议不在本轮强制做，避免扩大迁移和页面联动范围。

## Phase 6.4：患者端 Avatar 真实音频接入

### 目标

患者端训练入口和训练会话页在需要数字人口播时，先请求后端生成音频，再调用：

```ts
avatar.speak(text, audioUrl)
```

如果接口失败，则调用：

```ts
avatar.speak(text)
```

这样失败时仍可使用浏览器 TTS，不影响训练。

### 前端实现位置

建议新增/修改：

```text
frontend/src/api/training.ts
frontend/src/types/api.ts
frontend/src/views/patient/TrainingView.vue
frontend/src/views/patient/TrainingSessionView.vue
frontend/src/composables/useAvatarRuntime.ts
frontend/src/avatar/providers/static2d.ts
```

### 前端类型

在 `types/api.ts` 新增：

```ts
export interface AvatarSpeechPayload {
  scene: 'training_intro' | 'session_intro' | 'task_demo' | 'next_task' | 'result_encouragement' | 'error_recovery' | string
  session_id?: string | null
  session_task_id?: string | null
  text: string
}

export interface AvatarSpeech {
  text: string
  audio_file_id: string | null
  audio_url: string | null
  provider: string
  fallback: boolean
}
```

### 前端 API

在 `trainingApi` 新增：

```ts
createAvatarSpeech(payload: AvatarSpeechPayload) {
  return request<AvatarSpeech>(http.post('/training/avatar-speech', payload))
}
```

### 训练入口页接入

`TrainingView.vue` 当前已经有“听数字人说明”按钮。

建议改为：

```text
点击按钮
-> 组装 intro 文案
-> trainingApi.createAvatarSpeech({ scene: 'training_intro', text })
-> avatar.speak(text, audio_url)
-> 失败时 avatar.speak(text)
```

入口文案规则：

- 若今日推荐任务组未完成：说明今天的训练重点和任务节奏。
- 若有 `task_sequence`：说明“热身、主练、挑战”。
- 若已完成今日推荐：鼓励患者休息或自主轻量练习。

### 训练会话页接入

`TrainingSessionView.vue` 建议接入口播点：

| 时机 | scene | 文案 |
| --- | --- | --- |
| 创建/加载会话后 | session_intro | 今天我们先从这一组开始，我会一句一句陪你练。 |
| 展示当前任务 | task_demo | 请跟我说这一句：{target_text} |
| 开始录音 | listening 不请求 TTS | 我在听，你可以按自己的节奏说。 |
| 录音结束 | error_recovery 或 task_demo | 录音已保存，你可以先试听，再上传分析。 |
| 上传分析中 | thinking 不请求 TTS | 我正在整理这次训练结果。 |
| 单项完成 | next_task | 这一句完成了，我们进入下一句。 |
| 全部完成 | result_encouragement | 今天这一组完成了，做得很稳。 |
| 分析失败 | error_recovery | 这次分析没有成功，可以重新上传或再录一次。 |

其中 `listening` 和 `thinking` 状态不用请求 TTS，因为它们是状态提示，不应抢占患者录音或分析流程。

### 播放策略

建议新增一个前端辅助函数：

```ts
async function speakWithGeneratedAudio(scene: string, text: string, ids?: { sessionId?: string; sessionTaskId?: string }) {
  try {
    const speech = await trainingApi.createAvatarSpeech({
      scene,
      session_id: ids?.sessionId ?? null,
      session_task_id: ids?.sessionTaskId ?? null,
      text
    })
    await avatar.speak(speech.text, speech.audio_url)
  } catch {
    await avatar.speak(text)
  }
}
```

后续可以抽到 composable，本轮也可以先放在页面内，避免过早抽象。

## Phase 6.5：真实试用前稳定性补丁

### 目标

让数字人口播不会因为 TTS 服务失败、无声音样本、音频播放失败而阻塞训练。

### 后端稳定性

后端 `create_avatar_speech()` 应保证：

- `text` 为空时返回 400。
- `text` 过长时返回 400。
- 当前患者没有智能体时返回 400，提示“请先创建并选择智能体”。
- TTS Provider 异常时不要创建空文件。
- 异常信息不要暴露 API key、供应商原始错误全文。

MVP 可以选择两种策略之一：

1. 后端直接返回 500，由前端 fallback 到浏览器 TTS。
2. 后端 fallback 到 mock TTS，并返回 `fallback=true`。

本轮推荐第 1 种：

- 实现更简单。
- 和现有前端 fallback 逻辑配合清晰。
- 不会把真实服务失败伪装成成功。

### 前端稳定性

前端必须保证：

- TTS 接口失败时继续训练。
- 音频播放失败时显示数字人错误状态，但页面按钮仍可用。
- 患者开始录音前调用 `avatar.stop()`，避免数字人音频和患者录音同时发生。
- 上传分析中不播放新口播，只切换 `thinking`。
- 任务切换时打断上一段音频，播放新任务示范。

`Static2DAvatarProvider` 当前已经在 `speak(input)` 开头支持 `interrupt` 和 `stop()`，可继续复用。

## 五、测试方案

### 后端测试

建议新增 `backend/tests/test_avatar_speech.py`。

覆盖：

- 患者有当前智能体和 `voice_external_id` 时，创建口播成功。
- 返回 `audio_url` 为 `/api/files/{id}/content`。
- 生成的 `FileAsset.file_type == generated_audio`。
- 文本为空返回 400。
- 文本过长返回 400。
- 没有当前智能体返回 400。
- session 不属于当前患者时返回 404 或 400。

### 前端手动验收

启动前后端后按以下路径验证：

1. 登录患者账号。
2. 确认已有当前智能体，且至少上传过声音样本。
3. 进入 `/training`。
4. 点击“听数字人说明”。
5. 确认请求 `/api/training/avatar-speech`。
6. 确认返回 `audio_url`。
7. 确认数字人进入 speaking 状态并播放音频。
8. 进入训练会话。
9. 当前任务展示后数字人播放示范。
10. 点击录音时数字人停止播放并进入 listening。
11. 上传分析时进入 thinking。
12. 单项完成后进入下一项并播放下一项引导。

### 回归测试

建议执行：

```text
backend: pytest
frontend: npm run build
```

如果本地没有数据库或依赖，至少完成：

```text
backend/tests/test_process_engine.py
backend/tests/test_local_acoustic_provider.py
frontend npm run build
```

## 六、验收标准

本次迭代完成后应满足：

1. 患者端训练入口的数字人说明可以优先播放后端生成音频。
2. 患者端训练会话的任务示范可以优先播放后端生成音频。
3. TTS 失败时患者仍能训练，前端 fallback 到浏览器 TTS。
4. 所有训练口播音频保存为 `generated_audio` 文件资产。
5. 文件访问复用 `/api/files/{file_id}/content`。
6. 不改变现有训练评分、ASR、声学分析、推荐、报告结构。
7. 不引入真实 TTS 供应商硬依赖，mock 环境仍可完整演示。
8. 患者开始录音时不会残留数字人口播音频。

## 七、不在本轮做的事

本轮暂不做：

- Live2D 或 3D Avatar。
- 外部流式数字人 API。
- 完整数字人口播事件表。
- 治疗师端数字人配置后台。
- 患者长期聊天记忆。
- 个性化模型训练。
- 临床诊断或疗效承诺。

这些都可以后续做，但不应该阻塞当前试用闭环。

## 八、一次迭代执行顺序

建议按以下顺序实施：

1. 后端补 `TTS_PROVIDER` 配置字段和 provider `name`。

4. 后端新增 `/api/training/avatar-speech`。

本次迭代的收口标准不是“数字人更像真人”，而是：

```text

```

- Phase 6.6：接真实 TTS 供应商。
