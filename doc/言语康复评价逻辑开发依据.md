# 言语康复评价逻辑开发依据

## 1. 文档来源与适用范围

本文依据桌面 Word 文档《过程性监控+效果对比.docx》整理，作为后续“言语康复智能体”评价模块的开发依据。

本评价逻辑用于替代早期文档中偏通用的“内容表达、清晰度、流畅度、音量、提示依赖”五维单题评分框架。后续开发应以本文定义的“过程性监控 + 训练前后效果对比”为主线。

## 2. 总体评价框架

评价体系分为两类：

1. 过程性监控

用于训练过程中或单次训练任务后，基于患者实际输出进行量化记录。重点反映患者在脚本/任务输出中的正确生成情况、错误情况、言语速率和响度。

2. 训练前后效果对比

用于阶段性评估训练前后变化。重点使用标准化量表或问卷，对患者语言能力、交流能力和系统接受度进行对比。

## 3. 过程性监控指标

### 3.1 正确生成的脚本字数百分比

字段建议：

```text
correct_script_word_rate
correct_script_word_count
total_script_word_count
```

计算公式：

```text
正确生成的脚本字数百分比 = 正确输出的剧本总字数 / 剧本的总字数 * 100%
```

正确判定标准：

```text
剧本中字的发音错误不超过一个明显的音发错误。
```

明显的音发错误包括：

- 替换
- 变形
- 添加
- 遗漏

正常参考：

```text
100%
```

来源：

Youmans G, Youmans S R, Hancock A B. Script training treatment for adults with apraxia of speech[J]. American Journal of Speech-Language Pathology, 2011, 20: 23-37.

### 3.2 错误数

字段建议：

```text
error_count
error_events
```

错误定义：

```text
被认为没有交流意义的单词或短语重复、超过3秒的停顿、难以理解的发音以及插入语。
```

错误类型建议枚举：

```text
meaningless_repetition
long_pause_over_3s
unintelligible_pronunciation
filler
```

正常参考：

```text
0
```

### 3.3 言语速率

字段建议：

```text
speech_rate_wpm
valid_word_count
speaking_duration_seconds
```

计算公式：

```text
言语速率 = 总字数 / 说话时间
```

其中“字”的判定标准：

```text
非错误、具有交流意义。
```

应排除：

- “呃”“啊”等插入语
- 无意义重复
- 反复自我修正

正常参考：

```text
180-240 字/min
```

### 3.4 响度

字段建议：

```text
loudness_dba
```

正常参考：

```text
60-78 dBA
```

来源：

University of Sydney Voice Lab. Acoustic Analysis Normative Data Reference Sheet: V4.0[Z]. Sydney: University of Sydney, 2025.

## 4. 训练前后效果对比

训练前后效果对比不应等同于单次训练评分。它用于阶段性评估，建议在训练周期开始前和周期结束后分别采集。

### 4.1 WAB量表

用途：

```text
评估失语症相关语言能力变化。
```

关注维度：

- 自发言语信息量
- 流利性
- 语法能力
- 语序
- 可懂度
- 复述可懂度

来源：

- 王荫华. 西方失语症成套测验(WAB)介绍(一)[J]. 中国康复理论与实践, 1997,(2):87-89.
- 王荫华. 西方失语症成套测验(WAB)介绍(二)[J]. 中国康复理论与实践, 1997,(3):135-140.

### 4.2 CADL量表

用途：

```text
评估日常交流能力变化。
```

来源：

王哲. 基于韵律功能的脚本训练对非流畅性失语症言语可懂度的干预[D]. 华东师范大学, 2024. DOI:10.27149/d.cnki.ghdsu.2024.000514.

### 4.3 喜好度与接受度

用途：

```text
评估患者或家属对训练方式、陪伴智能体、声音形象和交互流程的主观接受度。
```

建议采集：

- 是否愿意继续使用
- 是否认为陪伴形象有帮助
- 是否认为声音反馈自然
- 是否认为训练任务可完成
- 是否产生压力或抵触

## 6. API返回建议

### 6.1 单次作答分析接口

`POST /api/attempts/{attempt_id}/analyze` 后续应返回过程性监控结果，而不是仅返回通用五维评分。

建议结构：

```json
{
  "process_monitoring": {
    "correct_script_word_rate": 100,
    "error_count": 0,
    "speech_rate_wpm": 190,
    "loudness_dba": 66
  },
  "reference_ranges": {
    "correct_script_word_rate": "100%",
    "error_count": "0",
    "speech_rate_wpm": "180-240字/min",
    "loudness_dba": "60-78 dBA"
  },
  "feedback": {
    "summary": "本次脚本输出完整，言语速率和响度处于参考范围。",
    "suggestion": "继续保持稳定输出，下一次可尝试减少停顿。"
  }
}
```

### 6.2 报告接口

报告接口应区分：

- 训练过程概览
- 过程性监控趋势
- 训练前后效果对比

建议结构：

```json
{
  "training_count": 10,
  "process_monitoring_summary": {
    "avg_correct_script_word_rate": 96.5,
    "avg_error_count": 1.2,
    "avg_speech_rate_wpm": 175,
    "avg_loudness_dba": 64
  },
  "effect_comparison": {
    "wab": {},
    "cadl": {},
    "preference_acceptance": {}
  },
  "suggestion": "继续加强脚本输出稳定性，并观察阶段性WAB/CADL变化。"
}
```

## 7. 开发原则

1. 不再将单次训练评价简化为“综合分 + 五维分”。
2. 过程性监控指标必须可追溯到原始录音、ASR文本、分词/字数统计和声学分析结果。
3. 训练前后效果对比必须与单次训练作答分离，作为阶段性评估数据保存。
4. WAB、CADL、喜好度与接受度属于评估量表或问卷数据，不应由模型自动伪造。
5. 第一阶段可以 Mock 过程性监控结果，但字段结构必须贴近本文定义。
6. 后续真实实现时，ASR负责转写和可懂输出基础，声学分析负责时长、停顿、响度，规则层负责错误判定和参考范围比较。

## 8. 与既有文档的关系

本文为后续言语康复评价逻辑的最高开发依据。

既有文档中以下表述应视为旧版本：

- 内容表达、清晰度、流畅度、音量、提示依赖五维单题评分
- `overall_score` 作为核心评价结果
- 单题反馈只展示分数和一个建议
- 训练总结展示“五维变化”

后续应改为：

- 单次训练展示过程性监控指标
- 阶段报告展示过程性监控趋势
- 训练前后效果对比使用 WAB、CADL、喜好度与接受度
