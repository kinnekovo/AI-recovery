# 实时数字人服务选型调研

日期：2026-09-27  
目标：患者可定制个人 2D 数字人，在 Web 训练中实时播报、打断和交互；继续使用本项目自己的 ASR、康复对话、评估与 TTS；优先中国大陆稳定性和低成本。

## 1. 最终建议

### 正式产品主选：腾讯云智能数智人

选择组合：

- 形象：`2D 小样本照片`，一张照片创建，19.9 元/个，官方说明照片形象永久有效；
- 交互：`2D 云渲染会话互动`，3500 元/月/路或 27000 元/年/路；
- 驱动：原声音频驱动，由本项目把现有 TTS 音频转换为 16 kHz、16 bit、单声道 PCM 后流式发送；
- 播放：H5 SDK / TRTC / WebRTC；
- 对话：继续由本项目处理，不购买或启用腾讯对话大脑。

腾讯不是目录价最低的云渲染服务，但它是目前调查中同时满足以下条件且综合风险最低的方案：

1. 中国大陆云服务和网络链路；
2. 官方公开价格，不需要先走商务询价；
3. 单张照片即可创建可用于云渲染交互的 2D 形象；
4. Web/H5 SDK、API、TRTC/WebRTC 齐全；
5. 支持原声音频驱动和播报打断；
6. 照片形象费用低，适合“一名患者一个形象”，没有海外产品常见的 1–10 个自定义形象槽位瓶颈；
7. 官方产品动态仍在 2026 年持续更新，2026 年 3 月还新增了 2D 云渲染音频驱动打断能力；本次未检索到产品整体停止新购公告。

### 最省钱的试点组合

```text
腾讯交互数智人体验包：140 元/天/1 路（页面标注 2D 精品）
使用体验包允许选择的官方形象验证实时链路
本项目既有 ASR、LLM/规则、TTS：继续复用
```

先购买 1–3 天体验包验证 SDK、建流、原声驱动、打断和降级，再决定是否购买照片形象对应的正式并发。腾讯明确提示不同形象类型的交互并发不能混用，体验包页面标注的是 2D 精品，**不能默认用于 2D 照片形象**。照片形象 PoC 前须让腾讯书面确认应购买的具体 SKU。若对应正式并发仍为目录价 3500 元/月，连续使用超过约 20 天时月包比 140 元/天更合理；年包 27000 元折合 2250 元/月。

### 长期成本主张：云服务增强 + 本地模式兜底

不要让每次训练都默认占用云路数：

- 个性化身份由现有本地 2.5D 照片形象免费承载；
- 需要高拟真展示或重点场景时才申请腾讯云路数；
- 并发满、弱网、服务异常时立即回到本地 2.5D；
- 通过真实使用率决定是否从 1 路扩容。

这能同时控制固定成本和供应商退出风险。

## 3. 为什么腾讯优于百度

如果只使用官方公共形象，百度云渲染确实更便宜：2400 元/月/路，对比腾讯 3500 元/月/路。

但本项目的核心要求是“患者自定义属于自己的形象”：

- 腾讯：2D 照片形象 19.9 元/个，可用于 2D 照片云渲染会话；
- 百度：20 元照片数字人主要用于端渲染照片交互 SDK；H5 端渲染 License 为 10000 元/月。百度 2400 元/月的云渲染支持的是定制 2D 小样本或精品形象，通用口型小样本需要 1–4 分钟视频且 1000 元/个；高级图生交互形象为 2000 元/个。

因此：

- 公共统一形象：百度更便宜；
- 大量患者个性化照片形象：腾讯总成本显著更低，也更符合现有创建流程。

## 4. 成本测算

### 场景 A：内部实时链路 PoC，官方形象测试 3 天

| 项目 | 腾讯 |
| --- | ---: |
| 1 路体验 3 天 | 420 元 |
| 合计 | **420 元** |

该体验包页面标注为 2D 精品，仅用于验证实时链路。不要在未确认 SKU 兼容性前购买照片形象并假定可以共用体验并发。

### 场景 B：100 名患者，1 路并发，使用一年

| 项目 | 腾讯 |
| --- | ---: |
| 100 个照片形象 | 1990 元（一次性） |
| 1 路云渲染年包 | 27000 元/年 |
| 首年合计 | **28990 元** |
| 次年基础成本 | **27000 元/年**（假定价格不变） |

1 路不是只能服务 1 名注册患者，而是同一时刻只允许 1 个云会话；患者可分时复用。并发占满时不排队，直接降级本地 2.5D。

### 场景 C：仅统一公共形象、不要患者照片

百度 2D 云渲染为 24000 元/年/路，理论上比腾讯年包低 3000 元。若产品愿意放弃个性化真人照片，可优先对百度做 PoC。

### 海外低价为什么不直接胜出

Anam $12/月看似远低于国内云服务，但套餐只有 2 个自定义形象槽位和 1 路并发；即使升级到 $999/月也只有 10 个形象槽位。Tavus $397/月也只有 7 个自定义形象槽位。它们适合“公司拥有少数固定数字员工”，不适合“每名患者长期保留一个个人形象”。

## 5. 腾讯接入方案

### 5.1 与现有系统的关系

现有 `AvatarProvider` 抽象继续保留：

```text
AvatarProvider
  ├─ Local2_5DProvider         默认与降级
  ├─ TencentCloudAvatarProvider 正式增强
  └─ AliyunCloudAvatarProvider  存量兼容，停止新增依赖
```

后端增加腾讯适配层，不改康复训练核心：

```text
患者录音
→ 现有 ASR / 场景对话 / 评估
→ 现有 TTS 生成回复音频
→ 转为 PCM 16kHz / 16bit / 单声道
→ 腾讯 SEND_AUDIO WebSocket
→ TRTC/WebRTC 视频流返回患者端
```

### 5.2 腾讯官方接口特征

- H5 SDK `driverType=3` 表示音频驱动（原声）；
- 支持发送音频和文本；
- 云渲染会话有 Initial、AudioStart、AudioOver、Error 等状态；
- 音频驱动要求 PCM、16 kHz、16 bit、单声道；
- 推荐按 160 ms / 5120 字节分片；读取离线音频时约每 120 ms 发送一包；
- SDK 5.5.0 以上支持音频打断；
- 主动关闭会话会释放并发路数。

### 5.3 迁移工作量

预计 5–8 个开发日：

1. `TencentCloudAvatarProvider` 前端适配与 H5 播放容器；
2. 后端签名、创建/关闭会话、心跳和租约；
3. TTS 音频转换与流式分包；
4. 播报打断、状态映射和本地降级；
5. 腾讯照片形象创建与异步状态映射；
6. 配置、健康检查、指标和自动化测试；
7. 弱网、移动端浏览器和单路并发验收。

## 6. PoC 验证清单

不要先买年包。按以下顺序验证：

1. 用腾讯官方形象和 1 天体验包跑通建流、关闭和并发释放；
2. 用项目现有 TTS 音频验证原声驱动，确认不会被腾讯 TTS 替换；
3. 验证点击录音后 300 ms 级打断，确保数字人和患者不抢话；
4. 创建 1 个 19.9 元照片形象，核实它确实能绑定云渲染会话；
5. Chrome、Edge、安卓微信/系统浏览器测试首帧、自动播放和麦克风权限；
6. 模拟断网、并发占满和供应商 5xx，确认训练自动降级且不中断；
7. 通过工单确认照片形象删除、数据留存、医疗场景和服务生命周期；
8. 通过后再买月包；连续稳定运行一个月后才考虑年包。

## 7. 采购前必须书面确认

即使选腾讯，也要避免再次遇到阿里式突然调整：

1. 19.9 元照片形象是否明确支持云渲染会话互动，而不只是视频制作；
2. 同一云并发能否在不同照片形象之间按会话切换；
3. 照片形象“永久有效”的准确含义及产品停止时的资产处理；
4. API/SDK 是否允许患者在产品内自助创建照片形象；
5. 照片、驱动音频、RTC 流和日志的存储地域、保留时间与删除机制；
6. 医疗康复场景是否需要额外协议或内容审核；
7. 年包内是否包含 TRTC/WebRTC 流量，还是另行计费；
8. 音频驱动是否支持当前期望的并发、超时和最长会话时长；
9. 产品停止服务的提前通知期限和存量合同保障。
