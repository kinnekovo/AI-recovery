# 言语康复智能体生产部署指南

本文档用于把当前项目部署到一台 Linux 服务器，适合小规模试用阶段。数字人当前按“可靠头像陪练”部署：用户上传头像，后端生成或回退到 mock TTS 音频，不依赖 Live2D、3D 或视频数字人服务。

## 1. 推荐架构

```text
Internet
  -> Nginx HTTPS
    -> /        frontend/dist 静态资源
    -> /api     FastAPI + Uvicorn
    -> /storage 不直接公开，统一通过 /api/files/{id}/content 鉴权访问

PostgreSQL
storage/ 本地持久化文件目录
```

生产环境第一阶段建议采用单机部署：

- 前端：`npm run build` 后由 Nginx 托管 `frontend/dist`。
- 后端：Uvicorn 作为 systemd 服务运行。
- 数据库：PostgreSQL 15+。
- 文件：服务器本地目录，例如 `/var/lib/speech-rehab/storage`。
- HTTPS：Nginx + 证书服务，或云厂商负载均衡证书。

## 2. 服务器准备

建议配置：

- 2 核 CPU、4 GB 内存起步。
- 40 GB 以上磁盘，训练录音较多时单独挂载数据盘。
- Ubuntu 22.04/24.04 或等价 Linux 发行版。
- Python 3.11+、Node.js 20+、PostgreSQL 15+、Nginx。

示例安装命令：

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip postgresql postgresql-contrib nginx
```

Node.js 建议使用 NodeSource、nvm 或服务器标准镜像安装，确认：

```bash
node --version
npm --version
python3 --version
```

## 3. 数据库

创建数据库和应用用户：

```bash
sudo -u postgres psql
```

```sql
CREATE DATABASE speech_rehab_agent;
CREATE USER speech_rehab_app WITH PASSWORD 'replace-with-strong-password';
GRANT ALL PRIVILEGES ON DATABASE speech_rehab_agent TO speech_rehab_app;
\q
```

PostgreSQL 15+ 可能还需要授权 schema：

```bash
sudo -u postgres psql -d speech_rehab_agent
```

```sql
GRANT ALL ON SCHEMA public TO speech_rehab_app;
\q
```

生产数据库连接示例：

```env
DATABASE_URL=postgresql+psycopg://speech_rehab_app:replace-with-strong-password@127.0.0.1:5432/speech_rehab_agent
DATABASE_CONNECT_TIMEOUT_SECONDS=5
```

## 4. 后端配置

后端目录：

```bash
cd /opt/speech-rehab-agent/backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

复制并编辑环境变量：

```bash
cp .env.example .env
chmod 600 .env
```

生产环境至少配置：

```env
SECRET_KEY=replace-with-long-random-secret
ACCESS_TOKEN_EXPIRE_MINUTES=1440
BACKEND_CORS_ORIGINS=https://your-domain.example

DATABASE_URL=postgresql+psycopg://speech_rehab_app:replace-with-strong-password@127.0.0.1:5432/speech_rehab_agent
DATABASE_CONNECT_TIMEOUT_SECONDS=5

STORAGE_ROOT=/var/lib/speech-rehab/storage

ASR_PROVIDER=mock
ACOUSTIC_PROVIDER=mock
TTS_PROVIDER=mock
LLM_FEEDBACK_PROVIDER=mock
SPEECH_EVAL_PROVIDER=mock
```

真实试用但还没有稳定第三方服务时，建议继续使用 mock provider，先验证训练流程、权限、报告和质控闭环。接入真实 ASR/TTS 后再逐项切换 provider。

创建文件目录：

```bash
sudo mkdir -p /var/lib/speech-rehab/storage
sudo chown -R www-data:www-data /var/lib/speech-rehab
```

如果后端服务用户不是 `www-data`，把目录所有者改成实际运行用户。

执行迁移：

```bash
cd /opt/speech-rehab-agent/backend
source .venv/bin/activate
alembic upgrade head
python scripts/check_database.py
```

## 5. 后端 systemd 服务

创建 `/etc/systemd/system/speech-rehab-api.service`：

```ini
[Unit]
Description=Speech Rehab Agent API
After=network.target postgresql.service

[Service]
User=www-data
Group=www-data
WorkingDirectory=/opt/speech-rehab-agent/backend
EnvironmentFile=/opt/speech-rehab-agent/backend/.env
ExecStart=/opt/speech-rehab-agent/backend/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

启动服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable speech-rehab-api
sudo systemctl start speech-rehab-api
sudo systemctl status speech-rehab-api
```

查看日志：

```bash
sudo journalctl -u speech-rehab-api -f
```

## 6. 前端构建

前端目录：

```bash
cd /opt/speech-rehab-agent/frontend
npm install
npm run build
```

当前前端默认请求 `/api`，生产环境只要 Nginx 把 `/api` 反向代理到后端即可，不需要把后端地址写进前端包。

## 7. Nginx

示例站点配置 `/etc/nginx/sites-available/speech-rehab-agent`：

```nginx
server {
    listen 80;
    server_name your-domain.example;

    client_max_body_size 20m;

    root /opt/speech-rehab-agent/frontend/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000/api/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

启用配置：

```bash
sudo ln -s /etc/nginx/sites-available/speech-rehab-agent /etc/nginx/sites-enabled/speech-rehab-agent
sudo nginx -t
sudo systemctl reload nginx
```

上线前必须配置 HTTPS。可使用云厂商证书或 Certbot，HTTPS 完成后把 `BACKEND_CORS_ORIGINS` 改为正式域名。

## 8. 发布顺序

每次发布建议按这个顺序：

1. 拉取或上传新代码。
2. 后端安装依赖：`pip install -r requirements.txt`。
3. 前端安装依赖并构建：`npm install && npm run build`。
4. 执行数据库迁移：`alembic upgrade head`。
5. 重启后端：`sudo systemctl restart speech-rehab-api`。
6. 检查健康状态：`curl https://your-domain.example/api/health`。
7. 用试用账号完成一次患者训练闭环。

## 9. 备份和恢复

至少备份两类数据：

- PostgreSQL 数据库。
- `STORAGE_ROOT` 下的头像、声音样本、训练录音、生成语音。

数据库备份：

```bash
pg_dump "$DATABASE_URL" > speech_rehab_$(date +%F).sql
```

文件备份：

```bash
tar -czf speech_rehab_storage_$(date +%F).tar.gz /var/lib/speech-rehab/storage
```

恢复时先恢复数据库，再恢复 storage，并确认文件路径和 `STORAGE_ROOT` 一致。

## 10. 上线检查清单

- `backend/.env` 不使用 `dev-only-secret`。
- `BACKEND_CORS_ORIGINS` 只包含正式前端域名。
- 数据库已执行 `alembic upgrade head`。
- `STORAGE_ROOT` 是持久化目录，不在临时目录。
- Nginx 不直接公开 storage 目录。
- `/api/files/{id}/content` 通过后端鉴权访问。
- `npm run build` 成功生成 `frontend/dist`。
- `/api/health` 返回健康状态。
- 管理员已分配治疗师-患者关系。
- 家属绑定处于确认后的 active 状态。
- 试用账号可完成一次训练、查看反馈、生成报告。

## 11. 当前限制

- 当前生产建议仍以 mock provider 或少量真实 provider 灰度试用为主。
- 真实 ASR、TTS、声学分析服务需要单独配置密钥、超时和失败回退策略。
- 高级数字人不在本阶段部署范围内，后续可在 Static 2D Avatar 稳定后升级。
