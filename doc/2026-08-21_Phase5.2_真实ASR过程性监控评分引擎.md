# Phase 5.2 基于真实 ASR 的过程性监控评分引擎

## 开发依据

本阶段严格依据 `言语康复评价逻辑开发依据.md`，不再以旧版“综合分 + 五维分”作为核心评价口径。

单次训练评价聚焦过程性监控：

- 正确生成的脚本字数百分比
- 错误数
- 言语速率
- 响度

WAB、CADL、喜好度与接受度仍属于阶段性评估，不由单次训练或模型自动伪造。

## 已落地内容

### 1. 独立过程性监控规则层

新增：

```text
backend/app/modules/evaluations/process_engine.py
```

规则层负责从目标脚本、ASR 转写文本和声学结果生成结构化 `ProcessEvaluation`。

### 2. 真实 ASR 文本脚本对齐

当前使用字级对齐计算：

- `correct_script_word_rate`
- `correct_script_word_count`
- `total_script_word_count`
- `script_mismatch_events.substitution`
- `script_mismatch_events.addition`
- `script_mismatch_events.omission`

其中“正确生成的脚本字数百分比”按：

```text
正确生成的脚本字数百分比 = 正确输出的脚本字数 / 脚本总字数 * 100%
```

### 3. 错误事件统计

当前支持：

- `filler`：插入语，如“呃、啊、嗯、额”
- `meaningless_repetition`：连续重复字符的轻量启发式统计
- `long_pause_over_3s`：来自声学 provider
- `unintelligible_pronunciation`：ASR 无有效输出时记为 1

脚本遗漏、添加、替换会记录在 `script_mismatch_events`，不直接混入错误数，避免把“脚本匹配度”和“过程错误事件”混成一个指标。

### 4. 言语速率

当前按：

```text
言语速率 = 有效交流字数 / 说话时间
```

有效交流字数会排除插入语和轻量重复事件。说话时间目前来自 acoustic provider。

### 5. 来源与限制标记

结果 details 中新增：

- `input_sources.asr_provider`
- `input_sources.acoustic_provider`
- `evaluation_source`
- `provider_version`
- `reference_ranges`
- `limitations`

当声学 provider 仍为 mock 时，会明确标记“响度、停顿和说话时长来自 mock”。

## 暂时兼容项

数据库与前端仍保留旧字段名：

- `script_accuracy`
- `error_count`
- `speech_rate`
- `loudness`

其中 `script_accuracy` 当前等价于 `correct_script_word_rate`。这是为了不一次性打断现有三端展示，后续 Phase 5 可逐步把前端文案统一成“脚本字数正确生成率”。

## 测试

新增标准库单元测试：

```text
backend/tests/test_process_engine.py
```

覆盖：

- 真实 ASR 完整匹配
- 脚本遗漏记录
- 插入语、重复和长停顿计数
- mock ASR fallback 显式标记

## 后续衔接

Phase 5.3 或后续阶段建议继续：

1. 接入真实声学分析，替换 mock 响度、停顿和说话时长。
2. 将前端文案从“脚本正确率”统一调整为“正确生成的脚本字数百分比”。
3. 在治疗师端展示 `script_mismatch_events`，便于复核患者主要是遗漏、添加还是替换。
