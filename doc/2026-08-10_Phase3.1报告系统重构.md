# 2026-08-10 Phase 3.1 报告系统重构

## 本次任务

将报告系统从旧的“综合分/平均分”聚合逻辑，迁移到 Phase 2 已建立的评价体系：

- 过程性监控：`script_accuracy`、`error_count`、`speech_rate`、`loudness`
- 阶段性效果对比：WAB、CADL、接受度

本阶段只实现报告接口和患者端 `/report` 页面重构，不新增数据库表，不实现能力画像和自适应训练推荐。

## 设计方案

重构原则：

- 报告不再以 `AttemptScore.overall_score` 作为主线。
- 报告聚合来自 `attempt_evaluations` 的 `mock_ai` 过程性指标。
- 阶段性变化复用 `assessment_sessions` 和现有 `compare_assessments` 逻辑。
- 没有训练数据或阶段评估不足时，返回可展示的空态结构，而不是伪造结论。

## 后端改动

更新：

```text
backend/app/modules/reports/schema.py
backend/app/modules/reports/service.py
```

`GET /api/reports/latest` 返回结构调整为：

```json
{
  "training_count": 10,
  "process_monitoring_summary": {
    "avg_script_accuracy": 95.0,
    "avg_error_count": 1.0,
    "avg_speech_rate": 150.0,
    "avg_loudness": 65.0
  },
  "effect_comparison": {
    "has_comparison": true,
    "wab": {},
    "cadl": {
      "baseline": 68,
      "current": 75,
      "change": 7
    },
    "acceptance": {
      "baseline": 8,
      "current": 9,
      "change": 1
    }
  },
  "suggestion": "过程性指标较稳定，可以结合阶段性评估变化继续推进下一轮训练。"
}
```

主要逻辑：

- `training_count` 统计已有过程性监控指标的 attempt 数量。
- `process_monitoring_summary` 按指标名称聚合均值。
- `effect_comparison` 复用阶段性评估对比结果，并拆分为 WAB、CADL、接受度。
- `has_comparison` 只有 baseline 和 current 为两条不同评估记录时才为 `true`。
- 建议文案根据脚本正确率、错误次数、语速、响度和阶段评估是否充分生成。

```text

```

预期：

- 阶段性变化摘要显示 WAB、CADL、接受度变化。
- 差值为当前评估减去 baseline 评估。
- 只有一条阶段性评估时不显示为完整对比。
