# 场景表达多轮对话训练与评价系统设计

## 1. 文档定位

本文是场景表达模块重新开发的主设计文件。它继承《场景表达：功能性沟通评价与迭代依据》的评价原则，并把单句自由作答升级为可追问、可澄清、可修复的多轮生活沟通。

与本文冲突的下列实现均视为旧版本：

- 把场景表达作为一次录音、一次评分的单句任务；
- 使用参考句、字符相似度或关键词覆盖率直接代表沟通成功；
- 让语速、响度、停顿或“错误次数”主导场景结论；
- 让 LLM 直接给出不可追溯的总分或临床结论；
- 在没有真实澄清回合时推测沟通修复能力。

## 2. 产品目标与边界

场景表达训练观察的是：患者能否在具体情境中发起或回应沟通，通过若干轮表达让对方理解需要，并在信息不足或被误解时继续补充。

跟读训练与场景表达必须使用两套独立流程：

| 项目 | 跟读训练 | 场景表达 |
| --- | --- | --- |
| 输入 | 固定目标句 | 场景、角色、沟通目标 |
| 交互 | 示范后复述 | 3～5 轮角色对话 |
| 内容评价 | 与目标句的复述表现 | 整段对话是否使听者能够行动 |
| 主要证据 | 对齐、发音和流利性 | 意图、信息单元、回应、独立性和修复 |
| 过程指标 | 可进入主要反馈 | 仅作为附属观察 |
| 结束条件 | 完成一次复述 | 达成目标、患者主动结束或达到轮数上限 |

## 3. 核心训练流程

一次场景训练对应一个 `dialogue_session`，内部包含多条 `dialogue_turn`：

```text
创建场景会话
  → 数字人以场景角色发起对话
  → 患者录音回答
  → 录音质量检查与 ASR
  → LLM 提取本轮语义证据
  → 规则层更新沟通状态
  → 对话策略选择追问、确认、修复或结束
  → LLM 生成受约束的角色回复
  → 重复以上过程
  → 汇总整段对话证据并评分
  → 患者反馈与治疗师复核
```

患者每轮只面对一个清晰问题。默认最多 5 个患者回合；达到 3 轮且目标已经充分达成时应自然结束，不为凑轮数继续追问。

## 4. 场景对话契约

每个场景模板必须具有版本化 `dialogue_contract`，至少包含：

```json
{
  "version": "scenario-dialogue-v1",
  "scene": "医院分诊",
  "agent_role": "分诊护士",
  "patient_role": "前来求助的患者",
  "opening_line": "您好，请问您哪里不舒服？",
  "communication_goal": "让分诊人员理解主要问题并能够安排下一步",
  "required_information_units": [],
  "optional_information_units": [],
  "completion_rules": [],
  "follow_up_questions": [],
  "repair_opportunities": [],
  "prompt_ladder": [],
  "minimum_patient_turns": 1,
  "maximum_patient_turns": 5,
  "difficulty": {
    "content_level": "L2",
    "autonomy_level": "S2"
  }
}
```

信息单元描述语义，不绑定唯一措辞。例如“提出获得药物帮助的请求”可由“想拿点药”“能给我开点药吗”“我想问问该吃什么药”等表达完成。

契约还应规定哪些信息在特定场景中并非必需。医院分诊与药店购药不能共用同一套完成条件，避免患者提出合理需求却因任务配置错误被低估。

## 5. 对话状态机

会话状态包括：

- `opening`：数字人发起场景；
- `collecting`：收集完成目标所需的信息；
- `clarifying`：表达含糊或信息不足，提出一个自然追问；
- `repairing`：安排一次真实的误解、确认或改述机会；
- `confirming`：复述已理解的信息，让患者确认；
- `completed`：目标达成并自然结束；
- `turn_limit_reached`：达到轮数上限；
- `aborted`：患者退出或技术失败。

每轮结束后由确定性策略选择下一状态，优先级如下：

1. 录音或 ASR 不可用：要求重录，不推进对话；
2. 患者请求提示：给出当前问题对应的最低等级提示；
3. 当前问题未被理解：进入 `clarifying`；
4. 必需信息不足：只追问最重要的一项；
5. 契约要求且尚未观察修复：进入 `repairing`；
6. 沟通目标满足：进入 `confirming` 或 `completed`；
7. 达到轮数上限：结束并标记尚未完成的信息。

LLM 不得自行决定修改完成规则，也不得通过暗示答案替患者完成表达。

## 6. LLM 的三个独立职责

### 6.1 角色回复生成

输入为场景契约、当前状态、已确认信息、尚缺信息和最近两轮对话。输出必须符合 JSON Schema：

```json
{
  "reply": "头疼多久了？",
  "dialogue_act": "clarify",
  "target_information_unit": "symptom_duration",
  "should_end": false,
  "safety_escalation": null
}
```

回复要求：一次只问一个问题；使用生活化短句；不宣称诊断；不提供具体用药决策；不评价患者对错。

### 6.2 语义证据提取

LLM 对本轮患者表达以及必要的上下文进行结构化抽取：

```json
{
  "intent": "寻求药物帮助",
  "answered_current_question": true,
  "relevance": "relevant",
  "information_units": [
    {
      "id": "symptom",
      "status": "supported",
      "quote": "有点头疼",
      "confidence": 0.96
    },
    {
      "id": "request",
      "status": "supported",
      "quote": "想来拿点药",
      "confidence": 0.94
    }
  ],
  "uncertain_items": []
}
```

证据必须引用患者原话。没有原文证据的单元不得标为 `supported`；无法确定时使用 `uncertain`，不得猜测。

### 6.3 患者反馈生成

LLM 只能根据已经确定的结构化结果，把反馈改写成尊重、简短、可行动的语言。它不得重新计算分数，不得添加规则层没有支持的优点、问题或临床判断。

三个职责使用不同接口、提示词版本和日志字段，不能用一个自由文本调用同时完成对话、抽取和评分。

## 7. 评分模型

评分对象是完整的多轮对话，而不是某一句话。正式维度如下：

| 维度 | 权重 | 计算原则 |
| --- | ---: | --- |
| 沟通目标达成 | 35% | 对方最终是否拥有采取合适行动所需的信息 |
| 关键信息充分性 | 25% | 必需信息单元在整段对话中的完成比例 |
| 对话回应能力 | 15% | 是否理解并回应当前问题、确认或澄清 |
| 场景相关性与组织 | 10% | 表达是否围绕当前情境且基本可理解 |
| 独立性 | 10% | 提示等级、请求帮助和启动等待 |
| 沟通修复 | 5% | 真实误解或追问后能否补充、改述或确认 |

### 7.1 确定性评分

LLM 只提供证据，规则层计算数值和等级。示例：

- 目标达成：`achieved = 100`、`partly_achieved = 60`、`not_achieved = 0`；
- 信息充分性：已确认必需单元数 ÷ 必需单元总数；
- 回应能力：有效回应回合数 ÷ 可评价患者回合数；
- 独立性：从 100 分扣除提示等级、主动求助与过长启动等待；
- 修复能力：仅对真实 `repairing` 回合评分，未安排则显示“未观察”，并从总分权重中移除后归一化。

场景主结果首先显示等级与证据，不以总分作为患者端视觉中心。数值主要用于治疗师观察和同难度长期趋势。

### 7.2 过程指标降级为附属观察

语速、响度、长停顿、重复、自我修正和可懂度仍逐轮记录，但：

- 不再使用“错误次数”概括自由表达；
- 不使用跟读参考范围直接给场景表达下结论；
- 不因患者说得更长而加分；
- 不输出“先练短句”等与本次沟通证据无关的模板反馈；
- 只有过程指标持续影响沟通时，才在次级区域给出一条建议。

## 8. 低置信度与冲突处理

以下情况不生成正式自动结论：

- 录音质量不合格；
- ASR 使用模拟或降级结果；
- 对关键单元的语义证据置信度低于配置阈值；
- LLM 输出无法通过 JSON Schema；
- LLM 证据引用无法在转写中找到；
- 同一证据被映射到相互冲突的单元；
- 对话契约缺失或版本不可识别。

系统最多重试一次结构化抽取；再次失败则保存原始材料并进入治疗师复核，不用关键词分数冒充语义判断。LLM 不可用时可以使用契约预设问题继续训练，但结果标为“仅完成训练，等待复核”。

## 9. 数据模型

建议新增：

### `scenario_dialogue_sessions`

- `training_session_id`
- `session_task_id`
- `contract_snapshot`
- `contract_version`
- `status`
- `current_state`
- `patient_turn_count`
- `prompt_count`、`maximum_prompt_level`
- `started_at`、`completed_at`
- `evaluation_role`

### `scenario_dialogue_turns`

- `dialogue_session_id`
- `turn_index`
- `speaker`：`agent` 或 `patient`
- `dialogue_act`
- `text`
- `audio_file_id`
- `asr_provider`、`asr_confidence`
- `prompt_level`、`requested_help`
- `quality_status`
- `semantic_evidence`
- `llm_provider`、`prompt_version`、`model_version`

### `scenario_dialogue_evaluations`

- `dialogue_session_id`
- `goal_status`
- 六个场景维度及可空修复分
- `overall_score`，仅供专业端和趋势使用
- `evidence_snapshot`
- `scoring_version`
- `confidence`
- `review_status`

已有单句 `attempt` 记录保留用于跟读。场景对话可将每个患者语音回合关联到一个 attempt，以复用文件、ASR 和声学能力，但汇总评价必须挂在完整对话会话上。

## 10. API 设计

- `POST /scenario-dialogues`：创建场景会话并返回数字人开场；
- `GET /scenario-dialogues/{id}`：恢复当前状态与对话记录；
- `POST /scenario-dialogues/{id}/turns`：上传本轮录音；
- `POST /scenario-dialogues/{id}/turns/{turn_id}/analyze`：完成 ASR、证据抽取和状态推进；
- `POST /scenario-dialogues/{id}/hint`：获取分级提示并记录独立性证据；
- `POST /scenario-dialogues/{id}/finish`：患者主动结束；
- `GET /scenario-dialogues/{id}/evaluation`：获取整段对话结果；
- `PATCH /therapist/scenario-dialogues/{id}/review`：治疗师复核证据与结论。

所有推进接口必须幂等，避免网络重试产生重复回合。服务端验证当前状态和 `turn_index`，客户端不能自行跳过状态。

## 11. 患者端交互

场景训练页改为对话界面：

- 顶部只说明场景和患者想完成的事；
- 中部按时间顺序展示数字人和患者回合；
- 当前数字人问题保持醒目，但不展示评分清单或标准答案；
- 每轮患者可录制、试听、重录后提交；
- “给我一点提示”只提示当前一步，并记录提示等级；
- 分析后由数字人自然追问，患者无需离开页面；
- 目标达成或达到轮数上限后才进入结果页。

结果页主结构为：

1. 对方最终理解了什么；
2. 患者在对话中提供了哪些关键信息；
3. 是否能够回应追问和完成澄清；
4. 下一次最值得练习的一件事；
5. 可折叠的语速、停顿和音量观察。

删除场景结果页顶部的“表达完整度、错误次数、语速、响度”四张跟读式主卡片。

## 12. 治疗师复核

治疗师看到整段音频与逐轮转写，而不是孤立的一句话。复核项包括：

- 沟通目标最终状态；
- 每个信息单元的支持证据及首次出现回合；
- 各追问是否得到有效回应；
- 是否真的发生沟通修复；
- 自动证据的漏识别、误识别和不确定项；
- 下一轮训练重点。

治疗师修正后重新运行确定性规则，不允许手工修改总分却不留下维度和证据。自动结果、原始结果和人工修订均保留版本。

## 13. 康复趋势与泛化

趋势以完整对话为统计单位，并分别显示：独立目标达成率、信息充分性中位数、有效回应率、平均提示等级和已观察修复成功率。跟读指标不得混入。

泛化小测使用未训练的平行对话契约，不进入日常推荐平均值。至少两个不同日期、两个可比新场景均独立达成目标后，才提示“可能发生泛化”。治疗师复核、WAB、CADL 和患者/家属报告仍是阶段性效果判断的重要独立证据。

## 14. 安全、隐私与可追溯性

- 医疗场景中的数字人只推进沟通训练，不诊断、不处方、不替代就医；
- 出现急症、安全风险或自伤相关表达时停止角色演练，使用经过审核的安全提示；
- 发送给外部 LLM 的内容遵循最小必要原则，不包含患者姓名等无关身份信息；
- 保存契约版本、提示词版本、模型版本、原始响应摘要、证据和规则版本；
- 日志不得记录密钥、完整敏感音频内容或未经脱敏的提供商异常；
- 临床校准前，LLM 语义评价必须明确标记为实验性证据。

## 15. 迁移与发布顺序

1. 新增多轮会话表、接口和契约校验，不改动跟读流程；
2. 实现确定性状态机和预设追问，使无 LLM 时也能完成训练；
3. 接入受约束的角色回复生成；
4. 接入结构化语义证据提取和证据校验；
5. 重做患者场景训练页与结果页；
6. 重做治疗师整段对话复核；
7. 接入场景专属趋势和泛化报告；
8. 用双人标注数据完成临床校准后，再逐步开放正式自动结论；
9. 删除或隐藏旧的单句场景入口，但保留历史记录只读访问。

发布采用功能开关。未完成整条链路前，测试环境可使用多轮版本，正式环境不得把半成品界面与旧单句评分混用。

## 16. 验收标准

只有同时满足以下条件，场景表达重新开发才算完成：

1. 患者可以连续完成至少 3 个有上下文关联的角色对话回合；
2. 数字人的追问由缺失信息和对话状态驱动，不是固定轮播；
3. “头疼，想拿点药”等合理自由表达可通过语义证据映射到症状和请求，而非依赖固定子串；
4. LLM 所有信息单元判断均有可定位的患者原话证据和置信度；
5. 证据校验失败或模型不可用时不生成正式自动总分；
6. 最终分数由版本化规则计算，修改证据后能够确定性重算；
7. 只有真实安排的澄清回合才能产生沟通修复评价；
8. 患者结果页不再使用跟读式四卡片作为场景主结果；
9. 治疗师能够逐轮播放、复核、修改证据并留下审计记录；
10. 场景趋势、跟读趋势和泛化探测完全分离；
11. 原始音频、ASR、契约、对话、LLM、规则和人工修订版本可追溯；
12. 自动测试覆盖状态推进、同义表达、无关回答、追问回应、提示依赖、修复成功、轮数上限、LLM 非法输出、低置信度和接口幂等；
13. 前端通过键盘操作、窄屏布局、加载/失败/重录/恢复会话等状态验收；
14. 临床结论继续遵循《场景表达临床校准与试点评估方案》的证据门槛。
