# 2026-09-03 G4 患者端模拟试用打磨记录

本记录用于 G4 的试用前模拟打磨，不代表真实患者反馈。真实试用开始后，应继续使用 `doc/言语康复智能体_试用反馈收集表.md` 收集患者、家属和治疗师反馈，再做下一轮患者端优化。

## 模拟场景

模拟对象：

- 第一次使用系统的患者。
- 旁边有家属或试用负责人少量协助。
- 使用手机或电脑浏览器完成一次跟读训练。

观察目标：

- 是否知道当前要说哪句话。
- 是否知道什么时候开始和结束录音。
- 麦克风失败时是否知道下一步。
- 录音完成后是否知道可以试听和上传。
- 是否能理解本次反馈不是临床诊断。

## 发现的问题

1. 录音组件没有录音时长反馈。
   - 风险：患者可能不知道是否已经开始录音，也可能过早结束。

2. 麦克风权限失败时，页面缺少清楚恢复提示。
   - 风险：患者以为系统坏了，而不是浏览器权限问题。

3. 训练页缺少简短的训练前确认。
   - 风险：环境噪声、没看清句子、没说完就停止会导致低质量录音。

## 已完成打磨

1. `RecorderPanel` 增加录音计时。
   - 录音中显示“已录 X 秒，建议说完一句后再结束”。

2. `RecorderPanel` 增加录音完成提示。
   - 录音后提示“可以先试听，觉得不清楚就重新录一遍”。

3. `RecorderPanel` 增加麦克风错误处理。
   - 开始录音失败时提示检查浏览器麦克风权限。
   - 停止录音失败时提示重新录一遍。

4. `TrainingSessionView` 增加训练前确认。
   - 显示“安静一点 / 看清句子 / 说完再停”。

5. `TrainingSessionView` 接入 recorder error。
   - 麦克风异常会同步到头像陪练状态，给出恢复提示。

## 后续真实试用重点观察

- 患者是否看得懂“说完再停”。
- 患者是否会主动试听录音。
- 麦克风权限错误是否仍需要人工协助。
- “上传并进入下一项”和“上传录音并生成反馈”是否足够清楚。
- 训练任务组是否过长，是否需要允许患者暂停后继续。
