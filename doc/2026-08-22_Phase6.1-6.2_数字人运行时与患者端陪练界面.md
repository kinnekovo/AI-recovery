# Phase 6.1-6.2 数字人运行时与患者端陪练界面

## 阶段目标

本阶段开始引入“数字人陪练”能力，但不把实现绑定死在某一种视觉形态上。目标是先建立可替换的 Avatar Runtime，再在患者端训练入口和训练会话中接入默认数字人陪练界面。

核心原则：

- 数字人只进入患者端训练体验，不进入家属端和治疗师端主流程。
- 训练业务仍由现有训练、录音、ASR、声学分析和评分链路承担。
- 数字人负责解释、示范、倾听状态、分析等待和鼓励反馈。
- 后续 Live2D、3D Avatar、外部数字人 API 都通过 Provider 替换，不重写训练页。

## Phase 6.1 已完成：Avatar Runtime 抽象

新增前端运行时抽象：

- `AvatarRuntimeState`
  - `idle`
  - `speaking`
  - `listening`
  - `thinking`
  - `encouraging`
  - `error`

- `AvatarProvider`
  - `kind`
  - `capabilities`
  - `speak(input, context)`
  - `setState(state, context)`
  - `stop()`

- `useAvatarRuntime`
  - `speak(text, audioUrl?)`
  - `listen(line)`
  - `think(line)`
  - `encourage(line)`
  - `fail(line)`
  - `idle(line)`

当前默认实现：

- `Static2DAvatarProvider`
  - 使用浏览器 `speechSynthesis` 进行中文 TTS 朗读。
  - 在朗读期间用轻量 mouth state 驱动口型开合。
  - 支持未来传入 `audioUrl`，用于接真实 TTS Provider 生成的音频。

## Phase 6.2 已完成：患者端数字人训练界面

### 训练入口页

患者进入训练页时新增“数字人陪练”面板：

- 解释今天是否需要完成建议任务组。
- 如果已有从易到难的任务序列，提示“热身、主练、挑战”的陪练节奏。
- 如果今日建议已完成，提示可自主安排训练或休息。
- 提供“听数字人说明”按钮，允许患者主动触发语音说明。

### 训练会话页

患者开始训练后，数字人会随训练状态切换：

- 创建训练会话后：示范当前任务文本。
- 患者开始录音：进入 listening 状态，提示“我在听”。
- 患者结束录音：提示录音已保存，可试听后上传。
- 上传并分析：进入 thinking 状态。
- 多任务组完成单项后：引导进入下一项。
- 分析失败：提示可重试或重新录音。

## 当前视觉实现

当前数字人视觉为默认 `static_2d`：

- 2D 半身形象。
- 说话时口型开合。
- listening / thinking / error 等状态有不同视觉反馈。
- 保持患者端友好、低压力，不使用治疗师端专业仪表盘风格。

## 后续可替换 Provider

后续可以在不改训练页面的前提下补充：

- `Live2DAvatarProvider`
  - 接 Live2D Cubism Web SDK。
  - 用 TTS 音频或音量包络驱动口型。

- `ThreeDAvatarProvider`
  - 接 Three.js + GLB Avatar。
  - 控制 idle / speaking / listening 动作和表情。

- `ExternalStreamingAvatarProvider`
  - 接 D-ID / HeyGen 等外部流式数字人。
  - 作为高级视觉模式，不作为训练核心链路依赖。

## 三端边界

| 端 | 本阶段变化 |
| --- | --- |
| 患者端 | 新增数字人陪练入口和训练会话陪练状态 |
| 家属端 | 无变化，仍只看陪伴概览、趋势和录音 |
| 治疗师端 | 无变化，仍看训练记录、趋势和自然语言调整入口 |

## 下一步建议

Phase 6.3 可以继续做“真实 TTS Provider 与数字人口播音频持久化”：

- 后端生成数字人口播音频。
- 前端 Avatar Runtime 传入 `audioUrl` 播放真实 TTS。
- 口型由音频播放状态或音量包络驱动。
- 患者端训练指令从文字优先转向“数字人先说、患者再练”。
