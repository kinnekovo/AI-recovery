# 2026-08-12 Phase 3.7 治疗师复核推荐与调参入口

## 本次目标

Phase 3.7 的目标是把 Phase 3.6 的“画像驱动系统推荐”升级为“系统生成、治疗师复核、患者端优先显示治疗师建议”的闭环。

本阶段继续坚持角色边界：

- 患者端只看到容易理解的训练建议、原因和备注。
- 治疗师端可以查看系统推荐依据，并确认或调整训练方向。
- 能力画像仍然作为客观计算结果保存，治疗师复核建议单独保存。

## 后端改动

### 1. 新增推荐复核模型

新增模型：

```text
TrainingRecommendationReview
```

数据表：

```text
training_recommendation_reviews
```

核心字段：

```text
patient_profile_id
recommended_type
headline
reason
focus_points
suggested_minutes
content_level
autonomy_level
confidence
profile_summary
review_status
reviewed_by_user_id
therapist_notes
```

复核状态：

```text
pending_review
confirmed
adjusted
```

### 2. 新增迁移

新增迁移：

```text
backend/migrations/versions/0007_training_recommendation_reviews.py
```

当前数据库版本：

```text
0007_rec_reviews
```

说明：

- 初版 revision id 曾过长，超过本地 `alembic_version.version_num` 长度限制。
- 已缩短为 `0007_rec_reviews`。

### 3. 推荐读取逻辑更新

患者端接口：

```text
GET /api/training/recommendation
```

现在会：

1. 先根据能力画像生成系统推荐。
2. 查询患者最新治疗师复核建议。
3. 如果存在 `confirmed` 或 `adjusted` 建议，则优先返回治疗师建议。
4. 否则返回系统建议。

### 4. 治疗师端新增接口

新增：

```text
GET /api/therapist/patients/{patient_user_id}/training-recommendation
```

用途：

- 给治疗师查看系统原始推荐。
- 不被已有治疗师覆盖建议影响。

新增：

```text
POST /api/therapist/patients/{patient_user_id}/training-recommendation/review
```

用途：

- 治疗师保存确认或调整后的推荐。
- 如果内容与系统推荐一致，状态为 `confirmed`。
- 如果修改训练类型、标题、原因、关注点或时长，状态为 `adjusted`。

## 后续建议

Phase 3.8 可以进入“推荐有效性反馈”：

- 患者完成按建议训练后，记录是否来自系统建议或治疗师建议。
- 治疗师端查看推荐后的训练表现变化。
- 初步判断“推荐是否有效”。
- 为后续 Phase 4 的推荐策略迭代提供数据。
